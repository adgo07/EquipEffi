## 12. Finalize Policy

已批准正式规则：

**允许 Finalize**：
```text
SUCCESS
OUT_OF_STANDARD_SCOPE
INSUFFICIENT_DATA
```

**不允许 Finalize**：
```text
INVALID_INPUT
EXECUTION_ERROR / internal system error
```

- `INSUFFICIENT_DATA`：**不强制**用户再次手填原因；保存系统已有的 `issue_codes`、`missing_fields` 与 `messages/explanation`；
- `OUT_OF_STANDARD_SCOPE`：属于**有效专业结论**，允许形成正式 Record；
- Finalize 必须验证结果仍对应当前 Workspace revision；改了参数或评价日期后不得保存旧结果；
- 快照、结果、lineage、audit 必须**同一事务**成功；失败不得出现可见的“保存成功”或不完整正式记录。

## 13. History / Reopen Policy

### 13.1 History
“分析记录”页面由 placeholder 变为真实页面，至少支持：
```text
Record 列表
日期
标准
产品类别
结论 / 等级
打开 Record
```
`water` Record 与 `chemical` Record 必须在**同一历史列表**；**不得建立两个历史库**。Phase 3 不做复杂搜索系统。

### 13.2 Reopen
必须**读取原 Record snapshot**。**绝对不得**：
```text
重新调用 evaluator
根据今天日期重算
根据最新 Canonical 重算
根据最新 Calculator 重算
```

**机械测试**：把 evaluator mock 为 `raise RuntimeError`，然后 `open_record(record_id)` 仍必须成功。

历史 Record 必须显示：原输入、原 `as_of`、原结论、原等级、原阈值、原依据、原引用。

### 13.3 Reproduce（仅定义语义）
Phase 3 **必须定义** reproduce 的语义与接口边界，但完整
`reproduce → new Record → lineage → old/new rule comparison`
**不是本 Phase 强制 Exit Gate**。不得为实现 reproduce 扩大 Phase 3 吞并后续完整生命周期工作。

**`Golden replay != Record reopen`**：前者用固定业务 Oracle 验证当前实现；后者读历史快照、不重算。

## 14. `as_of` Policy

产品负责人已决定；**这是软件产品决定，不是 GB 19762 发布机构的官方解释**（见 `STANDARD_ISSUES_REGISTER.md` / `EQP-STD-GB19762-001`）：

| 场景 | 行为 |
|---|---|
| 新建分析 | 默认 = 用户电脑**当前本地日期**；允许手动修改 |
| Evaluate / Finalize | 使用该 Workspace 中**实际**的 `as_of` |
| Finalize | 把实际 `as_of` **永久写入** Record |
| Reopen | 显示历史 Record 的**原** `as_of`，**不得**重新取今天 |
| Golden / regression replay | 测试 harness **显式**传固定日期 `2026-08-23`；该日期**只属于测试条件**，不是产品默认日期 |

- 正式产品模型中**不得**存在把 `date(2026, 8, 23)` 当作隐式默认的行为；统一 `AnalysisService` 采用**显式** `as_of`；
- **不得修改 18 条 `pump_water` Golden 来补 `as_of`**（这些记录本身不携带 `as_of`）；
- 既有 CLI/API 的兼容默认值按 `AGENTS.md §2.0` 作为兼容边界**登记保留**，全局取消须另立任务做兼容影响评估。
