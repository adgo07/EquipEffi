## 0. 只看一页：新 Agent 必须先做什么

### 0.1 必须阅读的文件

按顺序阅读，不要只读文件名：

1. `docs/26_多Agent可直接照做交付清单_v14_执行手册_20260905.md`（本文件）；
2. `docs/25_后续Agent可直接执行交付清单_v13_20260905.md`（最近基线和历史小任务）；

4. `HANDOFF_20260831.md` 的最后一个章节，以及与目标 profile 相关的历史章节；
5. `README.md`；
6. 目标评价器、标准包、相关测试，不要先读整个仓库。

### 0.2 领取规则

一个 Agent 一次只能领取：

- 一个任务 ID；
- 一个内部 profile；
- 一个标准边界或一个可审计的结果字段。

可接受的任务示例：

```text
T03.02-LV-MOTOR-POWER-UPPER-BOUNDARY
T03.03-HV-MOTOR-COOLING-MISS-TRACE
T03.05-WATER-PUMP-FLOW-INTERPOLATION
T03.11-HEAT-TREATMENT-FUEL-TYPE-MISMATCH
```

不可接受的任务示例：

- “把所有评价器都检查一遍”；
- “顺便重构标准仓库”；
- “把 Excel 导入写完”；
- “把所有测试跑一遍”；
- “按单调趋势修正标准值”；
- “顺手清理旧文件”。

领取前先查重：

```powershell
rg -n "T03\.02-LV-MOTOR-POWER-UPPER-BOUNDARY|<你的任务ID>|<目标边界关键词>" HANDOFF_20260831.md docs
```

已有相同目标、相同标准表和相同输入边界时，不得重复实现；应选择新的边界，或报告“停止并待确认”。

### 0.3 固定执行顺序

```text
只读预检
  → 标准证据卡
  → 先写一个必然失败的测试
  → 只运行失败测试
  → 最小生产代码修改
  → 目标测试
  → 相关矩阵/核心测试
  → compileall + diff-check
  → 只运行一次轻量完整回归
  → 追加 HANDOFF
  → 更新任务板和本次基线
```

任何一步发现标准冲突、证据不足、共享文件被他人修改或 CPU 持续高负载，都停止，不猜测、不扩大范围。

### 2.2 结论枚举

所有 profile 都必须支持四种公共结论：

```text
不在范围、无法判定、淘汰、未达标
```

另按设备类型允许的等级为：

| profile 范围 | 允许的等级 |
|---|---|
| 变压器、两类电动机、空压机、两类离心泵、两类通风机、潜水电泵、工业锅炉、四类 HVAC | `1级`、`2级`、`3级` |
| 鼓风机 | `节能评价值`、`能效限定值` |
| 热处理设备 | `一等`、`二等`、`三等` |
| 热泵热水机 | `1级`、`2级`、`3级`、`4级`、`5级` |

禁止把不属于该设备的等级混入结论。淘汰设备若参数完整，可以计算 `reference_conclusion`，但最终 `conclusion` 仍必须是 `淘汰`。

### 2.3 输入语义

- 所有值是出厂设计值、额定值或铭牌标称值，不写“实测”；
- 效率按百分数本值填写：`98` 表示 98%；普通效率允许 `1～100`，`0.98` 和 `101` 不能作为正常输入；
- 冷凝锅炉设计热效率可按标准例外允许 `1～110`，非冷凝锅炉仍为 `1～100`；
- 功率因数允许 `0～1`；COP、EER、SEER、APF 等比值只要求大于 0；
- 不能为了让样例通过而给缺失物理参数设置默认值；
- 不新增“设备位号”“是否在标准适用范围”字段；
- 不把“—”解释成 0、空白、缺失或可插值值；
- 不外推、不取最近档、不按经验单调趋势改标准值；
- 等于标准阈值时视为达到该等级，比较方向必须来自标准。

证据卡中的页码、表号和数值必须能在标准包或人工校对册中找到。找不到时写“未确认”，并停止；不得用搜索引擎摘要、旧 JSON 或经验趋势代替 PDF 原文。

### 5.1 标准包状态规则

```text
extracted → normalized → verified → active
```

- `active` 才允许进入正常判定；
- PMSM 旧 JSON、旧粗校对工作簿、旧清洗版和临时锁文件永远不允许加载；
- GB 28381-2026 已发布但 2027-04-01 才实施，本版鼓风机仍使用 GB 28381-2012；
- 标准实施日期早于 `as_of` 的问题由服务层处理，评价器不得自行绕过日期门禁。

## 6. 一项边界任务的逐步操作卡

### 第 1 步：只读预检

```powershell
Set-Location 'C:\Users\WANGWEI\.codex\worktrees\0dbc\EquipEffi'
Get-Location
git status --short
rg -n "<任务ID>|<目标函数>|<标准编号>|<目标 data_id>" HANDOFF_20260831.md docs src tests
```

确认：没有相同任务已经完成；目标文件没有他人正在改动；不需要删除、覆盖或移动用户文件。

### 第 2 步：最小阅读范围

优先读取：

1. 目标评价器的相关函数；
2. 目标标准 JSON 中对应表；
3. 已有同类成功/失败测试；
4. `EvaluationResult`、统一结果序列化和调用服务；
5. 历史 HANDOFF 中同 profile 的相邻边界。

不要一开始运行全量测试、全量 PDF 渲染、全量标准重建或 Excel 性能压测。

### 第 3 步：先写失败测试

测试必须只验证一个事实，且修复前真的失败。推荐结构：

```python
def test_<one_boundary>(self):
    result = self.evaluate("<public_type or internal_type>", {
        # 只填写该标准所需的设计/额定/铭牌字段
    })
    self.assertEqual(result.conclusion.value, "<预期结论>")
    self.assertEqual(result.standard_reference.get("standard_code"), "<标准号>")
    self.assertEqual(result.lookups[0].get("match_status"), "命中")
    self.assertTrue(result.trace)
```

如果修复前测试已经通过，说明边界选错或实现已经存在；不要为了“制造失败”改成无依据的输入。

目标测试命令：

```powershell
$env:PYTHONPATH='src'
python -m unittest tests.unit.test_device_evaluator_matrix.DeviceEvaluatorMatrixTests.<新测试名> -q
```

### 第 4 步：最小修改

## 8. 特殊规则速查

### 8.1 PMSM（永磁同步电动机）

- 唯一数据源：`gb30253_2024_pdf_verified_v1`；
- 表 1 的 55 kW、12 极，1/2/3 级均为“—”，命中必须为 `不在范围`；

### 8.2 电动机效率和冷却方式

- 效率输入范围为 `1～100`（百分数本值）；
- 高压 GB 30254-2024 当前标准冷却组只按标准列出的 `IC01/IC11/IC21/IC31/IC81W`、`IC611/IC616/IC511/IC516`、`IC411` 选择；
- 标准没有列出的冷却代码不能凭相似外观映射；应保留候选表和 `冷却方式未命中`。

### 8.3 淘汰目录

当前默认口径：`高耗能落后机电设备淘汰目录第一至第四批`。匹配必须记录：

```text

```

型号精确匹配或带边界的系列模式匹配后，功率、电压、机座号、年代等附加条件必须全部满足。疑似命中但缺条件时返回 `无法判定`，不能直接淘汰。产业目录仍是用户提供的受控子集，不得自行补全文本。

### 8.4 标准日期

`EvaluationService.evaluate(..., as_of=...)` 负责实施日门禁。评价器不应绕过服务层直接使用未来标准；早退时仍应保留已确定的淘汰和日期轨迹，不能把未来等级伪装成当前结论。
