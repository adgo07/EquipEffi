### 1.3 输入、结论和证据硬规则

- 输入参数代表出厂设计值、额定值或铭牌值；不要使用“实测效率”“实测功率”等字段名。
- 不得新增“设备位号”和“是否在标准适用范围”。
- 效率字段按百分数本值输入：98=98%；普通效率范围为1～100；冷凝锅炉设计热效率允许1～110。
- 功率因数范围为0～1；COP、EER、SEER、APF、IPLV等比值只要求大于0。
- 数量为正整数；功率、容量、流量、扬程、压力、损耗等正数必须大于0。
- `0.98`不能自动改写为`98`；清洗层只能保留原值并报告问题。
- 标准原文“—”表示该条件无标准值，不能当作0、普通空白、最近档或可插值端点。
- 结果必须区分“数据质量问题”和“能效结论问题”；自动备注不代替判定说明。

所有设备允许的通用结论为：`不在范围`、`无法判定`、`淘汰`、`未达标`。普通三级设备另有`1级/2级/3级`；鼓风机为`节能评价值/能效限定值`；热处理设备为`一等/二等/三等`；热泵热水机为`1级～5级`。

固定优先级：

1. 明确命中第一至第四批淘汰目录：`淘汰`。
2. 疑似命中但缺少附加条件，或产业目录未覆盖：`无法判定`。
3. 明确超出标准范围，或命中标准“—”：`不在范围`。
4. 缺少判定参数、标准查表条件或标准包未激活：`无法判定`。
5. 低于最低等级/限定值：`未达标`。
6. 其他情况按标准逐级比较。

淘汰设备如果参数完整，仍要保留参考能效等级、查表结果、计算值和完整轨迹；最终结论仍为`淘汰`。

## 3. 认领、执行、验收的固定闭环

### 3.1 认领消息

开始写文件前，在 Agent 回报或交接记录中写：

```text
【认领任务】T03.xx-<设备>-<边界>
【目标】只解决一个设备族的一个边界/一个结果字段/一个接口端口
【前置证据】标准编号、pack_id、标准状态、表号、条款、PDF页码、data_version
【允许修改】源码文件、测试文件、HANDOFF和本交接清单
【明确不改】标准JSON/PDF、人工校对册、V4模板、淘汰目录、Excel/SQLite
【失败测试】测试方法名和修复前失败现象
【预计命令】目标测试 → 相关组合 → compileall → diff-check
【停止条件】证据不足、标准冲突、共享工作区冲突、CPU高负载
```

### 3.2 标准证据卡

每个算法任务必须先填一张证据卡；缺任一关键项就停止写算法：

| 项目 | 必填内容 |
|---|---|
| `standard_code` | 如 `GB 20052-2024` |
| `pack_id` | 当前加载链路实际使用的包ID |
| 状态 | `extracted`/`normalized`/`verified`/`active` |
| 表号/条款 | 真实表号、公式号或章节号 |
| PDF页码 | 能回到原文页面；未知不得猜 |
| `data_version` | 标准资源中的版本标识 |
| 匹配轴 | 功率、容量、极数、转速、压力、流量、类别等 |
| 插值许可 | 标准明确允许的轴；不允许则写“禁止” |
| “—”语义 | 无数据、不作要求或不适用，必须按原文说明 |
| 比较方向 | `>=`、`<=` 或标准规定的组合 |
| 多指标逻辑 | AND、OR、固定门槛、分级指标分别写清 |

### 3.3 失败测试必须断言中间证据

测试不得只写 `assert conclusion == "1级"`。至少断言：

1. 标准编号、pack_id、表号、条款和页码（若资源已提供）；
2. `actual_metrics` 原样保留输入；
3. `calculated_metrics` 的公式输出或明确为空；
4. 每个等级的阈值/固定门槛；
5. 查表行、端点、系数、候选行或“—”标志；
6. 比较方向和逐等级 `passed`；
7. `missing_fields` 与 `data_quality_issues` 没有混淆；
8. `trace_schema_version == "1.0"`，并有对应 `rule_id`；
9. 早退时，已取得的证据没有被清空。

推荐测试名：

```text
test_<profile>_<boundary>_keeps_lookup_and_returns_<conclusion>
```

### 3.4 最小修改原则

- 一个回合只改一个评价器的一个语义边界；不顺手重构其他设备。
- 标准计算使用项目已有的 Decimal 工具；不要新增浮点近似或经验公式。
- 不外推、不自动取最近档、不把“—”转为0、不把缺参改成默认值。
- 查表、计算、比较和结论都要由评价器产生；API、窗口和报告只展示。
- 早退也保存已经读取的输入、候选、查表行、计算值和原因。
- 变更后优先跑定向测试，确认通过后再跑相关组合和轻量完整基线。

## 6. 统一结果契约验收卡

每个评价器的正常和早退结果都要可序列化，并保持这些键：

| 键 | 必须内容 |
|---|---|
| `conclusion` | 最终结论，任何路径都必须有 |
| `reference_conclusion` | 淘汰但仍完成评价时保存原始能效结论，否则为空 |
| `actual_metrics` | 已读取的设计/额定/铭牌值，早退不清空 |
| `calculated_metrics` | 已完成的标准计算，未计算用空对象/空值 |
| `limits` | 已查到的各级阈值或固定门槛 |
| `lookups` | 命中行、候选行、端点、插值系数、`data_id`、来源 |
| `comparisons` | 逐级比较、方向、阈值、是否通过 |
| `missing_fields` | 真正缺少或无法解析的判定字段 |
| `data_quality_issues` | 格式、单位、枚举、范围和冲突问题 |
| `standard_reference` | 编号、表号/条款、页码、pack、版本、状态、实施日期 |
| `elimination` | 目录名、批次、条目号、原文条件、命中原因、口径 |
| `elimination_match` | 兼容别名，不能形成第二份独立证据 |
| `trace` | 逐步轨迹；`trace_schema_version`必须为`1.0` |

每条轨迹步骤至少包含：`step_type`、`rule_id`、`input`、`output`、`unit`、`table`、`data_id/data_ids`、`match_conditions`、`endpoints`、`factor`、`direction`、`threshold`、`passed`、`standard_clause`、`elimination_scope`、`data_version`。不适用字段写空值，不伪造值。

### 6.1 早退分支最小矩阵

每个 profile 至少补齐以下分支中的适用项：

| 分支 | 预期结论 | 证据要求 |
|---|---|---|
| 必填字段缺失 | `无法判定` | 缺失字段列全；已读输入和已查候选保留 |
| 文本无法解析 | `无法判定` | 写入质量问题；不能当作范围外 |
| 合法数值超标准轴 | `不在范围` | 保留轴、候选行和“不外推”原因 |
| 标准“—” | `不在范围`或标准规定的其他语义 | 保留原文“—”、`no_data`和稳定data_id |
| 类别未知/冲突 | 通常`不在范围`或`无法判定` | 不默认套用最接近类别；保留候选和冲突字段 |
| 标准包未激活/实施日期未到 | `无法判定` | 记录包状态、实施日期和跳过原因 |
| 明确淘汰 | `淘汰` | 保存目录证据；可同时保存参考能效结论 |
| 低于最低等级 | `未达标` | 保存最低阈值和失败比较 |

## 7. 淘汰目录任务卡（第一至第四批）

任务ID：`T05-ELIMINATION-B1-B4`。本阶段只处理高耗能落后机电设备淘汰目录第一至第四批；产业结构调整目录待用户另行整理，不得扩充或改写。

### 7.1 匹配步骤

1. 规范化型号用于匹配，但保留用户原始型号。
2. 优先精确匹配；系列匹配必须使用边界明确的模式，不得使用无边界`in`或模糊相似度直接淘汰。
3. 功率、电压、机座号、结构、年代、型式等附加条件必须全部满足。
4. 条件齐全命中：最终`淘汰`。
5. 型号疑似命中但条件缺失：最终`无法判定`，不能写成“未淘汰”。
6. 两种口径只保留第一至第四批时，不得读取产业目录；默认口径为第一至第四批。
7. 目录未命中不代表安全；如果只启用产业受控子集，未覆盖项仍为`无法判定`。
8. 淘汰结果要继续保留已完成的标准计算和`reference_conclusion`。

### 7.2 必测样例

- 精确型号+全部条件命中；
- 系列型号在边界字符前后命中/不命中；
- 功率刚好等于上下限；
- 电压或机座号缺失；
- 型号相似但不是同系列；
- 目录命中但标准实施日期尚未到；
- 同一输入切换两种淘汰口径后的差异；
- 淘汰但能效参数完整，确认最终淘汰且保留参考等级。
