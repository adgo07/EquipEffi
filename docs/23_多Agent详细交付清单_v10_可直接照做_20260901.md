## 1. 交付目标、冻结范围和“完成”的定义

### 1.1 本阶段最终要交付的能力

1. 用一个公共15类接口选择设备，用17个内部profile执行标准差异化判定。
2. 评价结果同时保留输入值、计算值、查表值、比较过程、标准来源和淘汰匹配证据。
3. 对缺失、冲突、非法维度、超范围、标准“—”、未实施标准和淘汰疑似命中做可解释早退。
4. 结果可被核心服务、批量服务、Web、Tk模型、JSONL以及未来Excel/Android适配器复用。
5. 每个标准数值都能回到标准包的 `data_id`、表号、条款、页码和 `data_version`。

### 1.2 本阶段明确不做

- 不修改标准PDF、人工校对册、标准数值和标准状态。
- 不使用旧永磁同步电机JSON或粗校对资料。
- 不开发产业结构调整目录全文；现有产业目录只作为用户确认的受控子集。
- 不实现Excel正式导入、批量写回、嵌入图片、公式重算、保护解除和1500行性能压测。
- 不实现SQLite持久化、正式MSI、Android签名APK、Linux安装包或完整发布审计。
- 不在展示层复制任何标准公式或等级比较。

### 1.3 一个工作包何时才算“已完成”

必须同时满足：

- 只有一个任务ID、一个profile、一个语义边界；
- 有真实标准证据卡；
- 先有失败测试，再有最小修改；
- 定向测试和相关组合通过；
- `compileall`、`git diff --check`通过；
- 轻量完整组合实际通过；
- 结果契约和追溯字段未回归；
- `HANDOFF_20260831.md`已记录真实输出；
- 明确未完成事项，并且只给一个下一步。

证据不足时状态只能写“已停止/待确认”，不能为了通过测试而补猜标准值。

## 5. 统一结果契约：每条路径都要保留什么

评价结果必须能直接JSON序列化，关键键如下：

| 键 | 要求 |
|---|---|
| `conclusion` | 最终结论，任何路径都必须有 |
| `reference_conclusion` | 淘汰但参数完整时保存未考虑淘汰门禁的参考等级 |
| `actual_metrics` | 设计/额定/铭牌输入；早退不清空 |
| `calculated_metrics` | 已完成的标准计算；未计算用空对象/空值 |
| `limits` | 已查到的分级阈值、固定门槛和“—”标记 |
| `lookups` | 命中/候选行、表号、端点、结构化`capacity_boundary`（metric/min/max及开闭标记）、插值系数、`data_id`、来源 |
| `comparisons` | 每个等级的比较方向、阈值、通过与否 |
| `missing_fields` | 真缺少或无法解析的判定字段 |
| `data_quality_issues` | 文本、单位、枚举、范围和冲突问题 |
| `standard_reference` | 标准号、pack、状态、实施日期、表号/条款、页码和版本 |
| `elimination` | 目录、批次、条目号、原文条件、附加条件和命中原因 |
| `elimination_match` | 兼容别名；不得形成第二份淘汰证据 |
| `trace` | 完整步骤；`trace_schema_version`固定为`1.0` |

轨迹步骤至少包含：`step_type`、`rule_id`、`input`、`output`、`unit`、`table`、`data_id/data_ids`、`match_conditions`、`endpoints`、`factor`、`direction`、`threshold`、`passed`、`standard_clause`、`elimination_scope`、`data_version`。不适用项写空值，不伪造数值。

### 5.1 结论优先级

1. 明确命中第一至第四批淘汰目录：`淘汰`。
2. 疑似命中但附加条件不足：`无法判定`。
3. 明确超出标准范围或命中标准“—”：`不在范围`。
4. 缺少判定参数、标准未实施或标准包未激活：`无法判定`。
5. 低于最低等级/限定值：`未达标`。
6. 其余按标准逐等级比较。

淘汰设备参数完整时仍要继续查表和计算，`reference_conclusion`保留参考能效等级，但最终`conclusion`必须是`淘汰`。

### 5.2 各类允许结论

所有设备都有：`不在范围`、`无法判定`、`淘汰`、`未达标`。普通设备另有`1级/2级/3级`；鼓风机为`节能评价值/能效限定值`；热处理设备为`一等/二等/三等`；热泵热水机为`1级`至`5级`。

## 6. 各设备交付验收要点

以下是认领单一边界时必须回看的设备规则；标准原文优先于本表摘要。

### 6.1 变压器 `T03.01`

- 类别使用完整标准类别，不再拆成电压、绕组、调压方式三列。
- 基础输入：类别、额定容量、铁芯材质、绝缘耐热等级、连接组标号、空载损耗、负载损耗。
- 同一级空载和负载损耗必须同时达到；不能只看一项。
- 允许插值的容量轴必须由标准明确授权；不允许容量外推。
- 标准“—”或类别不命中时保留候选行和来源，不返回伪等级。

### 6.2 低压/高压/永磁同步电动机 `T03.02-LV/HV`、`T03.03`

- 效率按百分数本值：98合法，0.98和101不作为正常效率；不得自动改写原输入。
- 低压按标准表覆盖的三相异步电动机类型、功率、极数/转速查表；非支持类别不得套三相表。
- 高压按电压、冷却方式、功率、极数和表族路由；不能唯一选表时无法判定，不取最近表。
- 永磁同步只加载`gb30253_2024_pdf_verified_v1`；29张表的表题、功率、极数、转速、冷却、效率和“—”要可追溯。
- 永磁特例：表1、55 kW、12极，1/2/3级均为“—”，结论为`不在范围`，查表记录保留原文“—”和稳定`data_id`。

### 6.3 空压机 `T03.04`

- 型式、工频/变频、润滑、冷却、额定排气压力和容积流量/输入功率是离散/连续轴，缺一不能擅自取默认。
- 机组比功率的查表和比较方向要留在结果中；未命中不能取最近档或外推。

### 6.4 清水离心泵 `T03.05`

- 泵型类别直接决定表族；未知类别不得默认为单级单吸。
- 计算并保留输出功率、单级扬程、比转速、C1～C3和各级效率。
- 双吸、多级的流量/扬程转换必须在`calculated_metrics`和轨迹中写明。
- 正常和流量未命中都要保留表3的`source_pages`、候选行、边界和`data_id`。

### 6.5 石油化工离心泵 `T03.06`

以下六项已在v9逐项完成，后续Agent不得重复修改，除非出现新的PDF证据：

1. 正常lookup的`table=表2`、`source_clause=表2/公式(4)~(7)`；
2. 第一流量档`5<Q≤300`，Q=5为开下限；
3. 多级记录`stages`并使用单级扬程；
4. 第二流量档`Q>300`无99999人为上限，效率公式的`QBEP>3000按3000`仍单独保留；
5. `120≤ns≤210`规定点`η0=ηb`和偏移`+3/+1/-6`；
6. 比转速未命中时保留四段区间的开闭属性。

新任务应转到其他profile，不能把上述边界重新实现一遍。

### 6.6 通风机 `T03.07`

- 离心、轴流、外转子直联前向多翼等类别不能互相默认。
- 需要保留压力、压缩性修正、圆周速度、压力系数、比转速/轮毂比和结构修正条件。
- 结构修正条件缺失时应给出缺失/无法判定，不能当作无修正。

### 6.7 鼓风机 `T03.08`

- 当前只启用GB 28381-2012；GB 28381-2026已发布但未到实施期，本版不启用。
- 保留多变效率、`b₂/D₂`、级数、支撑方式、5.3.2/5.4.2条款、能效限定值和节能评价值。
- 多级缺级数不补1；标准“—”不是0。

### 6.8 潜水电泵 `T03.09`

- 从引用产品标准计算规定效率`ηDB`和效率容差`Δη`，保留ηSP、ηB、三级阈值及表4来源。
- 不默认效率或容差；“—”按标准语义保留。

### 6.9 工业锅炉 `T03.10`

- 蒸发量D和热功率Q至少一项；两项都空为无法判定。
- 燃烧方式、燃料、热值、挥发分和冷凝条件共同选表；冲突不静默选一行。
- 冷凝锅炉设计热效率允许1～110；非冷凝仍为1～100。

### 6.10 热处理设备 `T03.11`

- 按炉型和能源类型计算电炉/燃料炉可比单耗、燃料系数和α。
- 能源类型与总耗电/燃料耗量不匹配时写质量问题；不得用经验换算补值。
- 结论仅为一等、二等、三等或通用四类结论。

### 6.11 热泵和冷水机组、热泵热水机、三类空调 `T03.12`～`T03.16`

- 动态指标的名称和单位由设备类别自动确定；指标不适用不能填0代替。
- 多指标分清主指标、固定门槛、AND/OR通道；每个阈值和通过结果写入`limits/comparisons/trace`。
- 热泵热水机支持1～5级；其他普通设备只支持1～3级加通用四类结论。

## 17. 统一结果断言表（Agent 写测试时逐行核对）

| 场景 | `conclusion` | 必须保留的证据 | 不允许的行为 |
|---|---|---|---|
| 正常精确命中 | 对应等级或未达标 | 实际输入、命中 `data_id`、表号、条款/页码、阈值、逐级比较、轨迹 | 只返回等级，不给来源 |
| 允许插值 | 对应等级或未达标 | 两端记录、开闭属性、未舍入/舍入值、插值系数、来源 | 最近档、外推、先取整再比较 |
| 离散轴未命中 | 不在范围或无法判定（按标准语义） | 全部候选、输入轴、未命中原因、标准引用 | 自动映射到相邻类别/电压/极数 |
| 标准“—” | 通常不在范围或标准规定的早退 | 原文“—”、层级、`data_id`、表号/页码 | 当作0、缺失或低等级阈值 |
| 缺判定字段 | 无法判定 | `missing_fields`、已取得的部分计算/查表证据 | 用默认值补齐 |
| 文本/单位/枚举错误 | 无法判定或质量问题 | 原始值、规范化尝试、`data_quality_issues` | 静默改写原始输入 |
| 明确命中淘汰目录 | 淘汰 | 目录、批次、条目号、原文条件、命中原因、口径 | 用模糊相似直接淘汰 |
| 疑似淘汰但条件缺失 | 无法判定 | 疑似条目、缺失附加条件、匹配轨迹 | 把疑似当明确命中 |
| 已淘汰但参数完整 | 淘汰 | 仍保留参考能效等级、查表和计算过程 | 因淘汰而清空参考结果 |
| 标准未实施/包未激活 | 无法判定 | 标准状态、实施日期、数据版本 | 提前读取未生效指标 |

所有场景均应保持 `trace_schema_version == "1.0"`，并区分 `missing_fields` 与 `data_quality_issues`。任何早退都不能删除已经产生的中间证据。
