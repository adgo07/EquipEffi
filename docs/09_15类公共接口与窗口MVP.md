# 15类V4公共接口与窗口MVP

当前基线（2026-08-30）：GB 30253-2024 的29张表已完成用户逐表复核并处于 `active`；全量人工校对册61,958条记录均为“正确”。产业目录目前仍是按PDF核对的13条受控设备规则而非全文；在组合淘汰口径下，四批机电目录明确命中仍优先返回“淘汰”，产业子集未覆盖的型号保守返回“无法判定”。多级泵级数已在API和窗口共享的评价器中增加正整数门禁，范围/匹配提前结束时保留已经算出的指标上下文，变压器、电动机、通风机、潜水泵和锅炉也覆盖主要范围早退上下文。无V4契约时，API和桌面回退表单也复用同一套效率、整数、范围和非负数约束提示。当前建议交付目录为 `outputs/final_20260830_portable_provenance_v12/`，包含最新桌面契约同步、电压单位边界修正、Web表单字段去重和包内相对来源引用；Excel导入/回写继续只保留适配器接口，启动器不执行工作簿解析或回写。

## 已实施

本阶段将V4模板的15个设备sheet确定为对外公共设备类型：

`变压器｜电动机｜空压机｜离心泵｜离心通风机｜轴流通风机｜鼓风机｜潜水电泵｜工业锅炉｜热处理设备｜热泵和冷水机组｜热泵热水机｜风管送风式空调｜单元式空调｜多联式空调`

公共类型代码定义于`domain/evaluation/device_types.py`。原17类评价器仍作为内部profile保留：

- `电动机`路由到低压、高压或永磁同步电动机；
- `离心泵`路由到清水或石油化工离心泵；
- `离心通风机`和`轴流通风机`共用通风机评价器入口，但保留不同公共sheet和路由轨迹。

判定结果同时记录：

- `public_device_type`：V4公共类型；
- `internal_device_type`：实际使用的标准评价器；
- `公共设备类型路由`：路由依据和变化记录。

## V4契约

`application/services/v4_template_contract.py`提供V4配置sheet的解析接口。它接受V4配置行的字段ID、显示名称、分组、数据类型、单位、可编辑状态、必填条件、验证规则、范围和枚举名称，并向窗口和Excel适配器提供统一字段定义。

`infrastructure/excel/v4_reader.py`和`ooxml_reader.py`保留从内置V4工作簿读取配置字段、枚举集合和15个设备sheet非空数据行的适配器能力；当前产品入口不自动调用Excel读取。

`infrastructure/excel/v4_writer.py`保留结果列定点写回试验实现：按V4字段显示名称定位列，写入查表结果和能效等级，保留输入列、样式、公式及其他压缩包部件，并强制输出到新文件；按当前阶段边界，正式Excel导入/回写仍暂缓，待后续宿主显式接入。

`infrastructure/excel/v4_template_audit.py`提供只读模板验收：检查18个工作表、工作簿/设备表保护、禁止字段、公式错误、自动重算设置和媒体部件清单。写回器会保留输入工作簿中未识别的媒体部件，便于后续接入单元格图片锚点。

写回试验路径可增加隐藏的`判定轨迹`sheet，保存每条设备行的V4路由、输入规范化、淘汰检查、计算结果、查表、比较、标准版本和淘汰口径；当前手工/API判定不依赖该sheet。

V4模板已复制为软件资源目录中的只读副本，由`V4TemplateResource`管理并提供SHA-256指纹。下载操作只复制到新文件，不能覆盖软件内置模板。

## 窗口MVP

`presentation/desktop/main_window.py`提供跨平台桌面窗口MVP：

- 15类V4设备下拉选择；
- 淘汰判定口径下拉选择（默认第一至第四批机电目录）；
- 动态参数输入框；
- 参数判定和结果JSON展示；
- 下载空白模板按钮；
- 上传V4工作簿按钮；
- 模板下载和工作簿上传均通过`DesktopCallbacks`接口接入，窗口不直接依赖Excel库。

`presentation/api/application_api.py`提供无框架的公共API门面，包含15类列表、字段契约、公共类型判定和V4 sheet判定。后续可在其外层增加HTTP、WebSocket或安卓调用层。
门面同时提供`status()`能力状态快照，返回15类公共类型、17个标准包状态、PMSM安全门禁、淘汰目录条目数和当前可用口径，移动端可据此决定是否展示或禁用相应表单。
`schema(device_type)`除返回可编辑字段、单位、范围和枚举外，还返回`allowed_conclusions`及`conclusion_field`；普通设备仅允许通用四类结论+1～3级，鼓风机、热处理设备和热泵热水机分别返回其专用等级集合。
同一响应还返回`internal_profiles`及其标准包状态；例如公共“电动机”会明确列出低压、高压和PMSM，其中PMSM已完成29张表人工复核并处于`active`状态，可正常显示为可判定；表1、55 kW、12极的三档无数据命中仍按“不在范围”处理。
淘汰目录也改为通过`importlib.resources`读取，源码和wheel运行时均能看到第一至第四批可匹配条目；发布审计会检查目录资源存在且运行时条目数大于0。

启动方式：

```text
python main.py --gui
```

跨平台纯参数接口：

```text
python -m equipeffi --list-device-types
python -m equipeffi --device-type motor --json '{"category":"三相异步电动机（一般用途）", "rated_voltage":"0.4", "rated_power":7.5, "poles":4, "rated_speed":1480, "efficiency":98}'
python -m equipeffi --audit-template "设备能效分析空白模板_重构版V4_20260825.xlsx"
# 发布前只读审计（源代码、模板、校对册和可选wheel）
python tools/audit_release.py --wheel tmp/release-20260826/equipeffi-0.2.1-py3-none-any.whl
```

安装包可通过`equipeffi`命令调用同一公共API；Linux服务或安卓桥接层不依赖Tk窗口。

标准清单和标准JSON已复制到`src/equipeffi/resources/standards/`并由显式manifest加载，安装包不再依赖仓库外的标准目录。

窗口默认使用软件内置V4模板资源；也可以通过`EQUIPEFFI_V4_TEMPLATE`指定外部模板源。窗口现提供`YYYY-MM-DD`判定基准日期输入和标准/目录能力摘要，并与API/CLI写入同一判定轨迹。上传和导出按钮保留独立Excel适配器端口，当前只显示接口预留提示；本版本不提供环境变量旁路，待后续宿主完成适配器验收后再接入。

除Tk窗口外，`presentation/web/server.py`提供纯标准库浏览器窗口（`python -m equipeffi --web --open-browser`）。它动态读取同一V4契约，提供15类设备表单、状态和判定结果；内置空白模板可直接下载，工作簿上传通过无Excel依赖的`TemplateTransferPort`注入，默认仅返回接口预留提示，便于后续替换为桌面、Linux或安卓适配器。

## 当前限制

1. 窗口读取V4配置sheet失败时，才回退使用内部profile的兼容字段。
2. V4工作簿已通过真实OOXML两单元格图片锚点的写回保留测试，未知媒体部件不会被删除；仍需在桌面Excel客户端进行最终可视化复核，17类内部算法完整性仍需继续验收。
3. 窗口尚未打包为Windows安装包，也未建立Linux/安卓发布流程。
4. 设备算法和标准校对工作仍以现有完成度文档为准。
