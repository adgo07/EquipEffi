### 1.2 输入含义和数值边界

- 所有参数均为出厂设计值、额定值或铭牌值；禁止恢复“实测值”。
- 不得新增“设备位号”和“是否在标准适用范围”。
- 效率按百分数本值填写：`98` 表示 98%；普通效率为 `1～100`；冷凝锅炉设计热效率可为 `1～110`。
- 功率因数为 `0～1`；COP、EER、SEER、APF、IPLV 等比值只要求大于 0。
- 数量为正整数；功率、容量、流量、扬程、压力、损耗等正数必须大于 0。
- 清洗只能报告问题，不能把 `0.98` 自动改写成 `98`，也不能覆写用户输入。
- 标准原文“—”表示该条件没有标准值，不是 0、普通空值、最近档或可插值端点。

### 1.3 最终结论和优先级

所有设备都允许：`不在范围`、`无法判定`、`淘汰`、`未达标`。普通三级设备另有 `1级/2级/3级`；鼓风机为 `节能评价值/能效限定值`；热处理设备为 `一等/二等/三等`；热泵热水机为 `1级～5级`。

固定优先级：

1. 明确命中第一至第四批淘汰目录：`淘汰`。
2. 疑似命中但缺少附加条件，或产业目录未覆盖：`无法判定`。
3. 明确超出标准范围或命中标准“—”：`不在范围`。
4. 缺少判定字段、标准查表条件或标准包未激活：`无法判定`。
5. 低于最低等级/限定值：`未达标`。
6. 其余按标准逐级比较。

淘汰设备只要参数足够，仍须保存参考能效等级和完整查表轨迹；最终结论必须保持`淘汰`。

### 2.3 算法工作包固定顺序

1. 从实际加载链路找出 `pack_id`、标准编号、表号、页码和 `data_version`。
2. 写一个先失败的测试；测试必须断言查表候选、计算值、阈值、比较或缺失字段，不能只断言最终等级。
3. 只修改对应评价器和测试；不在 API、窗口、Excel 层复制公式。
4. 对未命中、字段缺失、标准“—”、范围外、条件冲突和早退路径，保留已经获得的查表/计算证据。
5. 运行目标测试和相关小组合。
6. 更新任务板、`HANDOFF_20260831.md` 和本文件状态；记录真实测试数字。

### 2.4 允许的停止结果

证据不足不是失败。可交付的“停止并待确认”必须说明：已查到的标准证据、尚不能确认的字段、没有改动的文件和下一步所需材料。禁止用经验公式、最近档、趋势修正、默认物理参数或模糊型号替代标准证据。

## 3. 统一结果契约：所有早退也要完整可审计

每次 `EvaluationService.evaluate`、批量 API、Web、Tk、JSONL 结果都必须保持下列键；新增键只能向后兼容：

| 键 | 内容 | 早退要求 |
|---|---|---|
| `conclusion` | 最终结论 | 必须有 |
| `reference_conclusion` | 淘汰但仍可计算时的参考能效结论 | 无参考计算时为空 |
| `actual_metrics` | 用户输入的设计/额定/铭牌指标 | 已读取的值不得因早退丢失 |
| `calculated_metrics` | 标准公式得到的指标 | 已计算的值不得因冲突丢失 |
| `limits` | 等级/固定门槛 | 已查到的阈值不得因缺失字段丢失 |
| `lookups` | 查表行、端点、系数、候选和来源 | 未命中也保留候选和原因 |
| `comparisons` | 逐级比较、方向、阈值、通过 | 至少记录已完成的比较 |
| `missing_fields` | 缺少的判定信息 | 只写真实缺失/冲突字段 |
| `data_quality_issues` | 输入质量问题 | 不混入能效结论 |
| `standard_reference` | 编号、表号、条款、页码、pack、版本 | 标准未实施也保留包信息 |
| `elimination` | 淘汰目录证据 | 目录名、批次、条目号、条件、原因 |
| `elimination_match` | `elimination` 的兼容别名 | 不得形成第二份可变证据 |
| `trace` | 逐步判定轨迹 | `trace_schema_version` 固定为 `1.0` |

每个 trace 步骤至少应包含：`step_type`、`rule_id`、`input`、`output`、`unit`、`table`、`data_id/data_ids`、`match_conditions`、`endpoints`、`factor`、`direction`、`threshold`、`passed`、`standard_clause`、`elimination_scope`、`data_version`。若某字段不适用，使用空值而不是伪造值。

## 4. 标准数据和淘汰目录门禁

### 4.1 标准包状态

状态只能按 `extracted → normalized → verified → active` 推进。机器 JSON 与人可读校对册必须通过稳定 `data_id` 一一对应。用户提出的修订值必须再次和 PDF 核对，不能直接覆盖机器数据。

### 4.2 PMSM 特殊门禁

- 只读 `gb30253_2024_pdf_verified_v1`；不得加载 `standards/motor_pmsm.json`、`standards2/motor_pmsm.json`、旧粗校对 Excel 或旧清洗版。
- 29 张表、表题、功率、极数、转速区间、冷却方式、效率和“—”都必须能回指 PDF 页码。
- 表 1、55 kW、12 极的 1/2/3 级均为“—”；命中时返回`不在范围`，并保留三条 `no_data=true` 查表记录和稳定 `data_id`。
- 未经 PDF 逐格复核的空白不得按单调趋势补值，不得激活新包。

### 4.3 淘汰目录

- 默认口径为“高耗能落后机电设备淘汰目录第一至第四批”。
- 产业目录只有用户提供并核对的受控子集；未命中不能解释为“未淘汰”，必须`无法判定`。
- 型号规范化后优先精确匹配；系列匹配需要有边界的模式和全部附加条件。
- 功率、电压、机座号、结构、年代等条件缺一不可；疑似命中但条件不足不能判`淘汰`。
- 轨迹保存目录名称、批次、条目号、原文条件、命中字段、原因和 `elimination_scope`。

### 5.1 每个 T03 设备任务的测试写法

测试文件统一优先使用 `tests/unit/test_device_evaluator_matrix.py`；跨服务早退使用 `tests/unit/test_evaluation_engine.py`。测试方法名建议：

```text
test_<device>_<boundary>_keeps_lookup_and_returns_<conclusion>
```

先写失败测试时至少准备：一组标准包真实输入、一组边界输入、一组缺失/冲突输入。每组都要断言：

1. 标准编号、pack_id、表号和来源页码；
2. 原始输入 `actual_metrics`；
3. 计算值 `calculated_metrics`（没有计算就明确为空）；
4. 每个等级的阈值/固定门槛；
5. 查表行、端点、插值系数或“—”标记；
6. 比较方向和逐级 `passed`；
7. `missing_fields`、`data_quality_issues` 是否分工正确；
8. `trace_schema_version == "1.0"` 和至少一个对应规则 ID。

## 6. 服务层、早退和淘汰测试卡

### 6.1 标准实施日期

标准包有可解析实施日期时，`as_of` 早于该日期不得调用评价器：

- 明确淘汰仍为`淘汰`，但不生成未来标准的 `actual_metrics/calculated_metrics/limits/lookups/comparisons/reference_conclusion`；
- 疑似淘汰为`无法判定`，保留目录证据和缺失条件；
- 产业目录非全文未命中为`无法判定`，不能输出未来标准等级；
- trace 记录 `standard_evaluation_skipped=true`、实施日期和原因。

### 6.2 参考能效证据

淘汰附加条件缺失或产业目录为受控子集时，如当前日期允许评价器运行，应先做只读评价：

- 最终结论仍按淘汰门禁返回；
- `reference_conclusion`保存评价器原始结果；
- 查表/计算/比较/标准引用和 trace 不得清空；
- 评价器自身缺参时不设默认值，安全回到`无法判定`。

### 6.3 目录匹配

至少覆盖：精确型号命中、边界系列命中、附加条件齐全、附加条件缺失、模糊相似不命中、两种 `elimination_scope` 不同。系列匹配必须测试边界字符，不能用无边界的 `in` 或模糊相似度直接判淘汰。
