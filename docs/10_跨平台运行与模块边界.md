## 核心安装

`equipeffi` 的判定内核、标准仓库、淘汰目录匹配、15类公共API和结果轨迹只依赖Python标准库。Linux服务端或安卓桥接层可仅安装核心wheel，不需要Tk、Excel或Word依赖。

V4模板的每个设备表在附件备注区之前保留隐藏“技术记录ID”系统列，用于把输入行、排序后的行和判定轨迹关联；它不是设备位号，不作为用户填写参数。空白首行通过非易失性表格计算列生成`sheet-行号`，读取器对旧文件仍使用相同回退规则。

仓库提供跨平台发布入口：

```bash
python tools/build_release.py --output-dir dist
```

该入口使用离线构建参数生成wheel，随后执行公共接口、17个内部profile示例、模板/校对册、标准门禁和隔离运行烟测；失败时保留产物并返回非零状态，便于审计，不会修改标准数据。
构建时可用`--review-book <路径>`显式指定人工校对册；未指定时优先寻找最新交付目录中的校对册，再回退到历史交付目录，避免审计误用旧版本。

最新 wheel 已在临时安装目录完成无 site-packages 烟测：安装后 `ApplicationApi` 可列出15类设备、读取能力状态（含第一至第四批淘汰目录条目），电动机示例返回“1级”，并能从已安装包读取多联式空调字段契约。该验证不初始化 Tk，也不依赖仓库根目录或 Excel。

```bash
python -m pip install equipeffi
equipeffi --list-device-types
equipeffi --device-type blower --json '{"category":"单级双支撑低速离心鼓风机","polytropic_efficiency":80,"impeller_width_mm":100,"impeller_diameter_mm":1000}'
```

批量 JSON 也可直接复用同一公共接口（不依赖 Excel）：

```bash
equipeffi --as-of 2026-08-23 --batch-json '{"records":[{"record_id":"B-1","device_type":"motor","values":{"category":"三相异步电动机（一般用途）","rated_voltage":"0.4","rated_power":7.5,"poles":4,"rated_speed":1480,"efficiency":98}}]}'
```

返回数组严格保持输入顺序；每条记录都返回完整的查表值、计算值、比较过程、淘汰匹配和缺失信息，格式与单条 `--json` 一致。`schema`还提供`result_fields`，列出锁定的标准结果和结论字段，供移动端或未来Excel适配器直接消费。Excel 读写仍通过独立适配器端口接入。
客户端可先调用 `equipeffi --status` 或 `ApplicationApi.status()` 获取标准包状态和淘汰目录能力；PMSM已完成29张表人工复核并处于`active`，表1/55 kW/12极的三档无数据命中会返回“不在范围”；产业目录未扩展为全文等限制仍会在能力快照中明确返回。wheel运行时同样通过包资源加载第一至第四批及已按PDF核对的2024年产业目录设备条目，不依赖源码目录。状态中的`entry_count`是当前已启用精确/受控系列匹配条目数（四批111条加产业规则13条）；`source_entry_count`按来源条目记录为413条（四批402+产业原文11项；产业目录拆分后的规则数为13条）；`industry_source_item_count`和`industry_resource_rule_count`分别明确返回11与13，`review_only_entry_count`为尚未安全启用的复核条目数，`catalog_status`为`normalized_pdf_verified_subset`，`industry_catalog_complete=false`表示仍非全文。全部记录可在发布审计和人工校对册中追溯，无法可靠映射的条目不会被强行启用。

来源PDF可通过 `tools/audit_release.py --industry-source-pdf <PDF路径>` 纳入发布审计；该选项会核对第134～137页的13条受控规则并比对资源中登记的SHA-256，不改变运行时目录范围。即使未提供PDF，发布审计也会检查产业资源的规则ID是否缺失、多余或重复；发现任一异常即阻断审计。

## 可选层

- `equipeffi[desktop]`：桌面Tk窗口（窗口只负责输入和展示）；若Tcl/Tk初始化失败，桌面启动器会自动回退到Web窗口。
- `--web`：纯Python标准库HTTP浏览器窗口，不要求Tk或第三方Web框架；浏览器表单、公共API和判定内核彼此独立。
- `equipeffi[tools]`：人工校对册、模板生成和标准提取脚本所需的openpyxl/python-docx。
- Excel适配器通过端口接入，输入/输出文件不是判定内核的依赖；移动端可替换为HTTP、JSON或原生文件适配器。

仓库还提供不下载网络依赖的本地wheel安装引导：`scripts/install_windows.ps1`和`scripts/install_linux.sh`。它们只创建/复用指定目录下的虚拟环境并安装wheel；Linux服务和安卓桥接层仍可跳过Tk，仅调用公共JSON接口。

如需交付一个可复制到目标机器的离线包，可运行：

```powershell
python tools/build_portable_bundle.py --wheel outputs/final_20260826/equipeffi-0.2.1-py3-none-any.whl --zipapp outputs/final_20260826/equipeffi-0.2.1.pyz --output outputs/final_20260826/equipeffi-portable-20260826.zip
```

便携包包含 wheel、可直接运行的`.pyz`、Windows/Linux 启动脚本、运行文档、JSONL/Android桥接协议说明和 `SHA256SUMS.txt`，不包含用户数据，也不宣称是原生安装程序；后续可在此基线上分别制作Windows、Linux和Android原生发布物。正式构建审计加 `--portable-output <zip路径>` 时会自动生成同目录`.pyz`并嵌入该包，也可用`--zipapp-output`指定路径；校对册验证器和`build_release.py`均可加`--require-activation`，把“所有记录正确且标准包active”作为发布失败条件。
本轮便携包同时收录`android/bridge/src/main/kotlin/com/equipeffi/bridge/JsonlBridgeClient.kt`协议客户端和Android接入说明；交付副本为`outputs/final_20260829_trace12/equipeffi-portable.zip`，包含18个成员并已通过清单、路径和SHA-256校验。该源码只负责行协议传输，不复制设备公式和标准数据，尚未声称为APK。

## 模块边界

```text
设备参数(JSON/原生表单) → ApplicationApi → EvaluationService
                                          ├─ 标准仓库/淘汰目录
                                          ├─ 设备计算器与查表器
                                          └─ 结果及判定轨迹
Excel V4读写器 ───────────────────────────┘（可替换适配器）
Tk窗口 ───────────────────────────────────┘（可替换展示层）
Web浏览器 ───────────────────────────────┘（可替换展示层）
```
