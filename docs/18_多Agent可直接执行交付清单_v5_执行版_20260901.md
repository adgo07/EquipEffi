## 0. 先读这一页：接手者必须遵守的总规则

### 0.1 本项目当前能做什么

- 输入一条设备参数，按公共15类设备路由到内部17个规则 profile，并返回结构化判定结果。
- 结果中保留：最终结论、参考结论、实际/标称指标、计算指标、标准阈值、查表结果、逐级比较、缺失字段、数据质量问题、淘汰命中证据和判定轨迹。
- API、Web、桌面表单、JSONL共用应用服务和同一套评价器；窗口不复制算法。
- 17个标准包可从 `src/equipeffi/resources/standards/` 加载；PMSM只允许新的 PDF 复核包。
- 第一至第四批高耗能落后机电设备淘汰目录已接入默认口径；产业目录目前只包含用户提供并核对过的受控子集。

### 0.2 本项目当前不能声称已完成什么

- 不能声称17类设备的所有标准边界、插值、特殊公式和现场样例均已验收。
- 不能声称Excel上传、结果回写、图片锚点、公式重算、保护和1500行性能已经交付；这些目前是接口/冻结项。
- 不能声称SQLite、Windows MSI、Linux安装包、Android签名APK已经交付。
- 不能把产业目录受控子集描述成《产业结构调整指导目录（2024年本）》全文。
- 不能把标准中的“—”当作0、普通空值、最近档或可插值值。

### 0.3 不可改变的业务门禁

1. 对外只能出现15类：
   `变压器、 电动机、 空压机、 离心泵、 离心通风机、 轴流通风机、 鼓风机、 潜水电泵、 工业锅炉、 热处理设备、 热泵和冷水机组、 热泵热水机、 风管送风式空调、 单元式空调、 多联式空调`。
2. 内部可以保留17个 profile，但只能通过 `profiles_for_public_type()` / `resolve_device_type()` 路由，应用层和展示层不能复制15→17映射。
3. 所有参数是出厂设计值、额定值或铭牌值；不得恢复“实测值”表述。
4. 不恢复“设备位号”和“是否在标准适用范围”。
5. 效率按百分数本值填写：`98` 表示98%；一般效率范围为1～100；冷凝锅炉设计热效率例外允许1～110；功率因数为0～1；COP/EER/SEER/APF/IPLV等比值只要求大于0。
6. 默认淘汰口径为“高耗能落后机电设备淘汰目录第一至第四批”。产业目录必须由用户提供并核对后才能扩展。
7. PMSM只使用 `gb30253_2024_pdf_verified_v1`。表1、55 kW、12极的1/2/3级均为“—”，命中必须为“不在范围”，并保留无数据查表证据。
8. 标准原文优先；无可靠标准证据时返回“无法判定”，不能用经验公式补全。
9. 自动备注只记录数据质量问题；能效逻辑、淘汰逻辑和标准不适用写“判定说明”和“判定轨迹”。
10. 只有标准明确允许时才能插值；不能外推、不能取最近档、不能擅自向上取整；等于阈值视为达到。

### 0.4 CPU和共享工作区规则

- 所有 Agent 共用同一个工作区；禁止两个 Agent 同时编辑同一模块。
- 同一时间只运行一个测试/构建进程；禁止并发构建 wheel、MSI、ZIP、PDF渲染和校对册。
- 日常只跑相关测试；完整测试只在交付前跑一次。
- 单次普通命令尽量在60秒内返回。预计超过60秒的任务先向用户报告。
- 严禁：`git clean`、`git reset --hard`、`git checkout -- .`、批量删除未跟踪文件、恢复旧根目录实现覆盖新 `src/`。
- 修改前必须查看 `git status --short` 和 `git diff --name-status`；不要为了“变干净”处理他人改动。

## 3. 工作协调协议：怎样分派给多个 Agent

### 3.1 分派原则

1. 一次只分派一个工作包；工作包完成并回报后，才能分派下一个。
2. 可并行的只读任务：阅读文档、审查测试、统计标准记录；任何写代码任务必须串行。
3. 一个工作包只能有一个主改动目录。例如 T03.04 只能改压缩机评价器和对应测试，不同时改元数据、Excel和发布脚本。
4. 如果任务需要改变标准数值、pack_id、淘汰目录或V4物理模板，必须停止并等待用户确认。
5. 每次改动前后保存同一输入的JSON结果；结果逐字段一致才算重构安全。

### 3.2 建议的任务认领信息

Agent开始前先在回复中写：


## 5. T01：V4单字段元数据迁移任务卡

### 5.1 选择范围

只选择一个V4中已经存在、类型/单位/边界/必填条件清楚且不需要修改算法的字段。优先额定功率、额定转速、正数容量等字段；不要从动态指标或尚未稳定的标准专属字段开始。

### 5.2 操作步骤

1. 用 `V4TemplateResource` / `V4WorkbookReaderImpl.read_contract()`读取字段ID、显示名、单位、数据类型、editable、上下界和必填条件。
2. 在 `domain/evaluation/metadata.py` 登记canonical field ID、V4 ID、显示名、单位、类型、别名、边界和来源 profile。
3. 检查 `presentation/metadata_projection.py` 是否能生成同一字段的API schema和桌面字段。
4. 在 `v4_validation.py` 增加字段级验证桥接；未迁移字段仍走旧常量回退。
5. 输入清洗只生成质量问题，不改写原始值。
6. 对同一字段加入：合法值、边界值、零、负数、文本、带空格、越界（若有上限）用例。

### 5.3 完成条件

- API、桌面、V4验证三处显示名/单位/范围相同。
- 原始输入字典在验证前后逐字段相等。
- 没有新增按设备复制的验证分支。
- 差异文件只涉及该字段、测试和交接记录。

### 5.4 停止条件

V4没有该字段、单位无法确定、标准“—”被误当数值、开放正数被擅自加上限、需要修改模板物理文件或标准包时立即停止。

### 6.1 可做内容

- 登记标准原文可证明的枚举值。
- 对前后空格、全角/半角、大小写、已确认同义词提供映射，但保留原始输入。
- 验证层拒绝非法枚举；自动备注再次检查批量粘贴绕过验证的非法值。
- 对数值文本、0、负数、效率超界和异常空格生成质量问题。

### 6.2 不可做内容

- 不把内部profile加入公共下拉。
- 不把无标准证据的词加入枚举。
- 不把“—”加入普通数值枚举或改成0。
- 不把“无法映射”强行改成某一个规范值。

### 6.3 每个枚举的固定用例

| 用例 | 预期 |
|---|---|
| 标准值 | 验证通过、无质量问题 |
| 明确非法值 | 验证失败或自动备注指出非法枚举 |
| 前后普通空格 | 原值保留，生成空格质量问题；若有可靠映射再记录规范化候选 |
| 全角/半角同义 | 仅在已有映射时给出规范化结果 |
| 批量粘贴非法值 | 即使绕过Excel验证，自动备注仍指出问题 |

## 8. T04：标准数据和人工校对册工作流

### 8.1 数据状态

机器标准包只能按以下状态前进：

`extracted → normalized → verified → active`

未达到 `verified` 的包不得标记 `active`。每条记录至少有：

`data_id、standard_code、table_number、product_category、matching_condition、original_range、structured_range、original_value、original_unit、normalized_value、normalized_unit、grade、comparison_direction、interpolation_rule、clause/page、source_file、review_status`。

### 8.2 人可读校对册

目标文件：`设备能效标准数据_人工校对版.xlsx`（如已有版本，先检查来源和状态，不覆盖）。应包含：校对说明、标准目录、逐标准平铺数据、公式/规则、分类/枚举、单位换算、淘汰目录四批、待校对问题、版本变更记录。

校对册中的标准值锁定；只有“校对状态、建议修订值、校对意见”可编辑。建议修订值必须再次与PDF核对后才能进入新的机器包。

### 8.3 PMSM专门门禁

- 只读取GB 30253-2024原始PDF重建的新包。
- 29张表每张都必须有表题、表号、页码、功率/极数/转速区间和“—”状态。
- 不使用历史678/685行数推断目标数据量。
- 不按单调趋势自动改值；趋势只用于发现待复核单元格。
- 任意一格看不清写“存疑”，不能猜。
- 旧文件（旧JSON、临时锁文件、粗校对电机表、旧分析表）不得出现在正式加载链路。

### 8.4 标准审计命令

只在标准数据确实变化或交付审计时运行，一次一个进程：
