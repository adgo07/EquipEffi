### 2.2 结论枚举和优先级

所有设备的公共结论：`不在范围`、`无法判定`、`淘汰`、`未达标`。

| profile类型 | 额外允许结论 |
|---|---|
| 普通三级设备（其余14类） | `1级`、`2级`、`3级` |
| 鼓风机 | `节能评价值`、`能效限定值` |
| 热处理设备 | `一等`、`二等`、`三等` |
| 热泵热水机 | `1级`、`2级`、`3级`、`4级`、`5级` |

统一优先级，除非标准明确另有更高优先级：

1. 明确命中当前淘汰口径的目录条目 → 最终结论 `淘汰`；
2. 疑似命中但附加条件缺失 → `无法判定`；
3. 明确超出标准适用范围或命中“—” → `不在范围`；
4. 缺少判定参数、标准未实施或标准包未激活 → `无法判定`；
5. 低于最低等级/固定限定值 → `未达标`；
6. 其他情况按标准逐级比较。

淘汰设备若参数完整，仍应保留 `reference_conclusion`、实际指标、计算值、查表值和轨迹；最终 `conclusion` 仍为 `淘汰`。

### 2.3 输入语义

- `efficiency`、`rated_efficiency`、`pump_efficiency`、`thermal_efficiency` 等百分数效率：范围通常为1～100，输入98而不是0.98；冷凝锅炉设计热效率按标准例外允许1～110。
- 功率因数：0～1。
- 数量：正整数。
- 容量、功率、流量、扬程、压力、损耗、转速、温度等正值字段：必须为正数，除非标准明确允许零或非负。
- COP/EER/SEER/APF/IPLV/HSPF等比值：只要求大于0，不套用百分数效率范围。
- 所有数值计算用 `Decimal` 或等价十进制定点语义；等于阈值视为达到。
- 不为缺失物理参数设置经验默认值；不外推、不取最近档、不把“—”当零。

### 3.2 证据要求

每个成功或早退结果至少保留：

- 实际输入及单位；
- 计算值、未舍入值（如适用）和舍入值；
- 查表候选、最终命中或未命中原因；

- `data_quality_issues`：文本空格、非法数字、负值、非法枚举、单位不可识别、字段冲突等输入质量问题。

- 不将“需确认”“应补充”写回数值输入；不把自动备注当作能效结论。

## 4. 标准数据工作规则

### 4.1 来源优先级

1. 标准原文PDF；
2. 逐项对照PDF的人可读校对册；
3. 已复核的粗校对表；
4. 旧JSON仅作历史线索，不能覆盖PDF和复核数据。

标准冲突时停止，记录冲突位置和待确认问题，不自行平均、猜测或按单调趋势改值。

### 4.2 标准包状态

统一使用：`extracted → normalized → verified → active`。

- `extracted`：从PDF/表格得到，未完成规范化；不得用于正式判定。
- `normalized`：字段、单位、区间和 `data_id` 已结构化；仍不得宣称已核对。
- `verified`：逐格与PDF核对，并有页码/表号证据；可进入激活审核。
- `active`：明确允许运行时加载。

新数据必须有稳定 `data_id`，且机器数据与人工校对册逐项一致。建议的数据记录字段：

```text
数据ID｜标准编号｜表号｜产品类别｜匹配条件｜原文区间｜结构化区间｜原文值｜原文单位｜规范化值｜规范化单位｜等级｜比较方向｜插值规则｜条款/页码｜来源文件｜校对状态｜建议修订值｜校对意见
```

### 4.3 PMSM硬门槛

- 唯一可加载包：`gb30253_2024_pdf_verified_v1`。
- 旧 `standards/motor_pmsm.json`、`standards2/motor_pmsm.json`、临时粗校对Excel和旧清洗结果不得被程序读取。
- 29张表均已人工复核；任一表发现新冲突，整个包暂停使用，返回“无法判定—标准数据待确认”。
- 表1、55 kW、12极：1/2/3级均为原文“—”；查表记录保留三档标记，比较不适用，最终为 `不在范围`。
- 不得按相邻功率/极数补值，不得按趋势自动修正。

### 4.4 淘汰目录硬门槛

当前可用口径：

- `仅产业结构调整指导目录`：只匹配用户已提供的受控子集；不是全文；
- `产业结构调整指导目录+高耗能落后机电设备淘汰目录第一至第四批`：默认口径。

匹配规则：原文型号和规范化型号同时保存；精确型号优先；系列型号使用有边界的模式；功率、电压、机座号、结构、年代、型式等附加条件必须全部满足。模糊相似不得直接判定淘汰。疑似命中但条件不足返回 `无法判定` 并列出缺失条件。实施日期未到的条目不得提前启用。

## 8. 低 CPU 和安全操作规则

### 8.1 默认允许

- 单个测试方法、一个测试模块、核心评价器组合；
- `rg`定位、少量JSON/Markdown读取、`compileall`、`git diff --check`；
- 读取单个标准表或单个PDF页作为证据；
- 一次轻量完整回归作为交付前最后验证。

### 8.2 默认禁止

- `python -m unittest discover` 全量发现；
- 全量PDF渲染、全量校对册重建、全量标准重新提取；
- 并行测试、并行发布构建、同时启动多个GUI/服务器；
- Excel 1500行压测、批量图片、公式重算或正式写回；
- 未经授权的安装包、签名、网络下载和系统级安装；
- `git reset --hard`、`git checkout --`、`git clean`、递归删除或覆盖用户文件。

### 8.3 CPU异常处理

如果CPU持续接近100%：

1. 立即停止当前长命令；
2. 保存已产生的测试输出，不重复启动；
3. 只保留目标测试和静态检查；
4. 在交接中写明命令、持续时间和是否恢复；
5. 若无法在低 CPU 模式完成，状态写“部分完成/停止并待确认”，不要伪造完整回归。
