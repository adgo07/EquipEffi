## 0. 使用方式

1. 每个回合只认领一个任务 ID 和一个明确边界。例如 `T03.04-B03`，不要同时修改元数据、评价器、Excel 和发布脚本。
2. 先只读确认工作区和标准证据，再写一个会失败的测试；测试失败原因必须是目标缺口，而不是环境错误。
3. 只修改任务卡列出的文件。需要改标准 JSON、PDF、人工校对册、V4物理模板、淘汰目录或公共结果键时，立即停止并等待用户确认。
4. 评价器改动必须保留 `actual_metrics`、`calculated_metrics`、`limits`、`lookups`、`comparisons`、`missing_fields`、`standard_reference`、`elimination` 和 `trace`；提前返回也不能丢掉已获得的查表证据。
5. 每次完成后运行本卡的最小测试、`compileall` 和 `git diff --check`，再更新 `HANDOFF_20260831.md`；不要把未运行的测试写成已通过。
6. 同一工作区只允许一个写代码/测试进程。发现其他长任务、PDF渲染或构建正在运行时，停止并报告，不开第二个进程。

### 1.1 不得改变的输入语义

- 所有输入都是出厂设计值、额定值或铭牌值，不写“实测值”。
- 没有“设备位号”和“是否在标准适用范围”。
- 效率按百分数本值输入：`98` 表示98%；普通效率允许 `1～100`；冷凝锅炉设计热效率允许 `1～110`；功率因数允许 `0～1`；COP/EER/SEER/APF/IPLV 等比值只要求大于0。
- 标准“—”表示该档没有要求，不是0、空值、最近档或可插值值。
- 只有标准明确允许的插值可以实施；禁止外推、取最近档、经验公式和趋势修正。
- 通用结论为 `不在范围｜无法判定｜淘汰｜未达标`；普通设备另有 `1级/2级/3级`；鼓风机为 `节能评价值/能效限定值`；热处理设备为 `一等/二等/三等`；热泵热水机为 `1级～5级`。

## 3. 每个工作包的固定执行协议

### 3.1 认领消息（先发给项目负责人）

```text
认领任务：<任务ID>
目标：<一个字段、一个边界或一个设备族的小闭环>
目标文件：<绝对路径>
前置证据：<标准编号、pack_id、表号、页码、data_version>
本次只改：<源码/测试/交接文档>
明确不改：标准JSON、PDF、人工校对册、V4模板、淘汰目录、Excel/SQLite（除非任务卡明确授权）
失败测试：<测试模块.测试方法>
预计验证：<最小测试 + compileall + diff-check>
停止条件：<证据不足/冲突/共享工作区冲突/CPU限制>
```

### 3.2 算法任务的强制顺序

1. 找到正式 `pack_id`、标准编号、表号、来源页码和 `data_version`。
2. 用标准原文或已确认校对数据写失败测试；测试应断言中间结果，不只断言等级。
3. 修改对应 `src/equipeffi/domain/evaluation/evaluators/<设备>.py`。
4. 查表未命中、字段缺失、标准“—”、范围外或冲突早退时，保留候选行、`data_id`、查询条件、页码、条款和已计算值。
5. 运行本卡测试；再运行设备矩阵和评价引擎相关小组合。
6. 仅当机器数据确实变化且用户确认后，才新增 `pack_id/data_version`；普通规则修复不要改标准资源。

### 3.3 统一结果断言

```text
最终结论：conclusion
参考结论：reference_conclusion
实际/标称值：actual_metrics
计算值：calculated_metrics
各级阈值：limits
查表记录：lookups（含 data_id、表号、页码、条件）
逐级比较：comparisons（含方向、阈值、是否通过）
缺失字段：missing_fields
数据质量问题：data_quality_issues
标准引用：standard_reference
淘汰证据：elimination / elimination_match
轨迹：trace，版本必须为1.0
```

### 6.1 T03测试模板

每个设备至少增加以下场景；设备标准不支持的场景写明“标准不适用”，不能伪造输入：

1. 精确命中：命中唯一行，断言标准值和来源。
2. 等于阈值：按标准比较方向通过。
3. 低于最低等级：返回 `未达标`，保留逐级比较。
4. 允许插值：断言两个端点、未舍入系数、舍入值和来源。
5. 禁止插值/外推：返回 `不在范围`，保留候选行和禁止原因。
6. 缺少关键字段：返回 `无法判定`，缺失字段明确列出，已有计算和查表不丢失。
7. 标准“—”：返回 `不在范围` 或标准规定的结果，断言原文值为“—”，不出现数值0。
8. 淘汰优先级：命中目录时最终为 `淘汰`，完整参数仍可保留参考能效等级。

## 7. T05：淘汰目录卡

### 7.1 当前范围

- 默认只使用高耗能落后机电设备淘汰目录第一至第四批。
- 产业目录只使用当前受控子集；不得声称已覆盖《产业结构调整指导目录（2024年本）》全文。

### 7.2 可执行步骤

1. 先检查 `src/equipeffi/resources/elimination_catalog_batches_1_4.json` 的目录名、批次、条目号和条件。

5. 轨迹记录目录、批次、条目号、原文条件、命中字段、命中原因和 `elimination_scope`。

### 7.3 最小用例

精确命中、系列边界内/外、功率不满足、电压不满足、附加条件缺失、两种淘汰口径差异、淘汰后继续保留参考等级。
