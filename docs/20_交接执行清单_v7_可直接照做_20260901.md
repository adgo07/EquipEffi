### 1.2 输入语义

- 所有参数均是出厂设计值、额定值或铭牌值；不得恢复“实测值”。
- 不得新增“设备位号”和“是否在标准适用范围”。
- 效率按百分数本值输入：`98` 表示 98%；普通效率允许 `1～100`；冷凝锅炉设计热效率允许 `1～110`。
- 功率因数允许 `0～1`；COP、EER、SEER、APF、IPLV 等比值只要求大于 0。
- 数量为正整数；功率、容量、流量、扬程、压力、损耗等正数必须大于 0。
- 标准原文“—”不是 0、普通空值、最近档或可插值值。

### 1.3 结论集合和优先级

所有设备都可返回：`不在范围`、`无法判定`、`淘汰`、`未达标`。

普通设备另有 `1级/2级/3级`；鼓风机另有 `节能评价值/能效限定值`；热处理设备另有 `一等/二等/三等`；热泵热水机另有 `1级～5级`。

结论顺序固定：

1. 明确命中淘汰目录：`淘汰`。
2. 淘汰条件可能命中但信息不足：`无法判定`。
3. 明确超出标准适用范围或标准“—”：`不在范围`。
4. 缺少判定参数、查表条件或标准包未激活：`无法判定`。
5. 低于最低等级/限定值：`未达标`。
6. 其余按标准比较得到等级。

淘汰设备在参数完整时仍计算并保存参考能效等级；最终结论保持 `淘汰`。

```text
停止条件：证据不足、标准冲突、共享工作区冲突或CPU限制
```

### 3.2 算法任务顺序

1. 找到实际加载的 `pack_id`、标准编号、表号、来源页码和 `data_version`。
2. 用标准原文或已确认校对数据写一个会失败的测试；必须断言中间结果，不能只断言最终等级。
3. 只改对应 `src/equipeffi/domain/evaluation/evaluators/<设备>.py` 和对应测试。
4. 查表未命中、字段缺失、标准“—”、范围外、冲突或提前返回时，仍保留已获得的候选行、`data_id`、查询条件、页码、条款和计算值。
5. 运行本卡测试，再运行设备矩阵和评价引擎小组合。
6. 更新本清单的任务状态和 `HANDOFF_20260831.md` 的新章节；写明实际测试数字。

### 3.3 不允许的捷径

- 不用最近档、经验公式、趋势修正或未经标准允许的插值。
- 不把效率 `0.98` 自动改写成 `98`；清洗只报告问题，不改写原始输入。
- 不把标准“—”改成 0、空白可比较值或插值端点。
- 不因为输入字段缺失而伪造默认物理参数。
- 不在窗口、Web、JSONL 或 Excel 层复制标准公式。

## 5. 结果契约：每个早退也要保留

任何入口返回的对象至少应能序列化出以下键；新增字段只能向后兼容：

```text
conclusion              最终结论
reference_conclusion    淘汰时仍可计算的参考能效结论
actual_metrics          用户输入的设计/额定/铭牌指标
calculated_metrics      由标准公式得到的指标
limits                  各等级或固定门槛
lookups                 查表行、端点、系数、候选及来源
comparisons             每一级比较、方向、阈值和是否通过
missing_fields          缺失的判定字段
data_quality_issues     只记录输入质量问题
standard_reference      标准编号、表号、条款、页码、pack_id、data_version
elimination             淘汰证据
elimination_match       elimination 的兼容别名，不得形成第二份可变证据
trace                   完整步骤，trace_schema_version 固定为1.0
```

轨迹步骤建议至少包含：

`step_type｜rule_id｜input｜output｜unit｜table｜data_id/data_ids｜match_conditions｜endpoints｜factor｜direction｜threshold｜passed｜standard_clause｜elimination_scope｜data_version`。

早退时要特别检查：

- 已完成的查表不能被后续缺失字段覆盖。
- 候选未命中要保留候选表/行及稳定 ID。
- 插值要保留未舍入系数、端点和舍入结果。
- 无数据要保留原文“—”，不能写成数值 0。
- 自动备注只写数据质量；能效和淘汰原因写判定说明/轨迹。
