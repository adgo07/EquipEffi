## 4. 数值核验方法及可复现证据

1. `extract_tables.py`只读原PDF；临时副本旋转用于坐标提取，原件不重存。pdfplumber按空间顺序提取；PDF自定义字体没有正常Unicode数字映射，故以原页图像抄录的锚点建立逐页字形对应。锚点原值及字形表保存在 `glyph_anchors.json`，共25行视觉锚点（含单页双表及破折号）。
2. 原文每行每列的解码结果写入静态工作簿。数值是Excel数字类型，破折号保留文本。没有以历史JSON、旧程序、旧Excel补真值，也没有Excel业务算法。
3. `verify_workbook.py`通过另一解析器pypdf从**原PDF**直接抽取字形序列，对全部204行与pdfplumber空间分行结果复核。204/204一致。两者共享PDF文字层，不构成独立图像转录。
4. 只读重开已保存XLSX，按真实坐标逐格对照：3582格全部值匹配，其中3093个效率数字、285个破折号、204个功率数字。原文整数/一位小数写法逐格检查对应Excel格式，0处差异。每行来源三列亦核对。
5. `cell_verification.csv`逐格保存PDF SHA、表号、物理页/印刷页、原页数据行、功率/极数/等级、Sheet/单元格、原字形、解码显示值、XLSX值及显示格式、第二解析器检查标记。`verification_summary.json`是对应汇总，不能只用行数替代数值证据。

字形映射不跨页默认复用；同一个抽取字符在不同字体可能分别表示数字和破折号。本次通过原页确认数据区独立单字形为破折号；任何未来原文SHA变化须重做字形锚点。PDF11的页码“7”与末行220kW同一文本行，初稿提取漏该行，已按原图识别并修复提取，最终表3完整35行、204全行双解析比对一致。此为提取过程修复，不是标准数字纠正，不应新增“标准笔误”。
