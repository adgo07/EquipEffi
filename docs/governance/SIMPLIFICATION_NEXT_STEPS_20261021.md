## 2 设计原则与当前边界

标准依据及运行资产沿用[标准档案总入口](../standards/README.md)：标准原文 → 经确认的主映射及配套表值 → 已有结构化运行数据和 Calculator。标准事实、专业判断、软件决定和问题状态各归既有入口；运行时不解析映射 Markdown 或校对工作簿，不将它们变成第二套算法，也不把原文打入最终软件。

当前离心泵评价继续复用已验证的正式业务链；公共层只承担现有调用方确实共用的职责，标准专属计算和判定留在对应标准实现中。不能要求其他标准经过泵专属服务。新增公共接口必须有当前实际调用方；仅代码相似、未来可能用到，都不足以支持抽取。

当前允许：业务名称、单位、选项、共同输入约束和结果含义同源；必要调用接线；重复装配或职责收拢。当前暂缓：变压器及其他新标准的接入设计/开发、Word 新功能、新平台能力、UI 美化、页面重排、跨软件视觉统一，以及为这些未来能力预建服务/页面/配置/测试骨架。原生 Windows 构建验收仍是正式发布前未完成项，本轮不开展发布工程。

## 3 执行顺序与每批交付

### 第二批：应用层实际公共职责去重（优先）

目标：完成一至两处有实际收益的职责收拢，减少同一业务含义需要同时修改的地方。

1. **短调用盘点。** 只核对 Qt、正式 Excel 和与候选项有关的兼容入口。起点为已有 `composition.py`、泵单台/批次服务、结果投影及生命周期接口。记录调用方、定义所在、重复职责、必须保留的差异、替代后原实现如何退出。把一张短表放进本批执行摘要，不新建长期调用台账。
2. **选择一处，最多两处。** 候选包括重复参数组装、身份传递、公共结果定义或服务装配；选择条件是业务语义确实相同、有多个当前调用方、兼容边界清楚、能够给出替换前后证据。旧 API 迁移仅为候选；若涉及历史日期门禁、输入或兼容语义差异，优先选择更清晰的职责，不顺手改变已登记差异。
3. **最小实现与实际接线。** 优先复用现有接口和元数据，不以文件大或函数长为由拆层。Qt/Excel 已共享的结果投影和 `create_pump_analysis_service` 不重复建设；服务实例是否共用须结合状态和生命周期，不能仅按构造代码相似决定。业务规则、精确路由和标准版本来源不复制到页面/适配器常量。
4. **同步退出重复实现。** 同批删除已被替代的独立定义，必要兼容入口只保留转换/转发和回归。单台每次合法分析独立保存、批次仅一条 batch_record、历史读取原快照，这些既有行为差异不合并。
5. **独立验收后结束该批。** 主会话检查选定范围的 diff 和相关验证，在固定 Head 提交一个 PR。若盘点未找到值得合并的真实重复，记录证据并结束盘点，不为了交付数量硬造抽象；接口/候选的普通取舍由主会话处理，无需再次请 Owner 多身份审批。

交付只需：重复点前后对照、最小实现及接线、原实现处置、相关验证。表中应能回答“原来哪几处分别维护，现在由哪一处负责”。不以减少总代码行数、增加公共模块数量作为验收标准。

### 第三批：现有字段与结果定义同源

以第二批实际稳定的接口为前提，限于已存在功能：字段名称、单位、业务选项、共同必填条件/取值要求、结果名称与结论文字、标准版本/来源信息。先检查已有契约和元数据，只合并重复维护的业务含义，不重造业务 Schema。

| 内容 | 责任位置与处理原则 |
|---|---|
| 业务定义与规则 | 对应标准已有契约/元数据或 Calculator；共同部分同源，标准差异保留 |
| 输入格式转换 | GUI/Excel 各自适配，例如文本框转换与单元格读取，不强行合并 |
| 页面布局、列位置、样式 | 保留各载体定义；本批不重排页面、不建设通用表单生成器 |
| 结果显示 | 复用已有投影；固定结论用语和输入错误/执行失败/未支持状态继续分开 |

完成证据：选定定义只有一个可维护来源，GUI 和 Excel 的实际路径都使用它，原重复定义已退出。只为接入公共实现修改必要 UI 接线；不做配色、图标、字体、间距或跨软件视觉对齐。涉及 UI 接线时按中央当前指南检查相关部分，不扩成全界面重构。

### 第四批：剩余旧路径与维护资料收尾

集中处理前两批留下的明确事项：退出有已验证替代的旧实现，收拢重复用途脚本/维护入口，精简活跃文档的重复状态和过时说明，处理影响现有正式功能的已登记缺陷。前两批能同步退出的重复逻辑不得故意留到本批。

旧资产沿用 KEEP / VERIFY / MIGRATE / REWORK / DEPRECATE / DELETE_CANDIDATE / OBSOLETE 分类；零引用或文件名带 legacy 不能作为删除依据。JSON/Web/Tk/Android/V4 等现存兼容/开发表面按用途、实际调用和登记差异处置。个人文件、用户工作簿、未提交资料继续留待第三方核实，不混入仓库清理；标准开发原件保留。

已有基线失败按精确 ID 核对 QA_BACKLOG，复用已有条目、缺项才补，优先处理影响正式泵功能或可靠验收的问题。不要求先清零全部历史失败；不得扩大允许名单、删测试、改 Golden 制造绿灯；真实修复并有证据后才收紧相应基线。

## 4 Excel 版本与受保护行为

- 工作簿修订、各设备 Sheet 契约、实际标准/数据/计算器版本分开；实际模板识别来源单独保存，不猜测、不冒充业务版本。
- 全设备统一 Workbook，清水/化工泵共用离心泵 Sheet。当前不接通新设备；已有未支持 Sheet 不计算、不删改。以后恢复新设备接入时再沿用逐 Sheet 接通、全部已支持 Sheet 回归的规则。
- 原始基线不覆盖；结构实际变化才产生新修订，并明确旧版兼容/另存迁移路径。未知、不兼容的字段或单位明确拒绝。
- 输出始终另存，未处理 Sheet 的顺序、内容和样式保持；不固定 Table 行数，不让用户逐 Sheet 配置容量。
- 29 条 Approved Golden、Decimal50/全值比较、标准身份、记录资格、单台/批次保存语义和历史快照继续保护。受保护资产与冻结双文件不借清理修改。

| 步骤 | 谁负责 | 输出及依赖 |

| 候选定界 | 主会话 | 选一至两项及文件边界；普通实现取舍自主决定 |
| 实现 | C 线为主；涉及 Excel 再启用 X 线 | 接口/所有权确定后可并行准备回归；有依赖的接线串行 |
| 其他工作 | P 线仅在确有资源、脚本或打包改动时启用 | 无对应改动则不启动，不为并行制造工作 |
| 复验与提交 | 主会话 | 固定 Head，相关独立检查，失败退回原线修正；每批一个明确范围的 PR |

只保留现有关键检查，新增验证针对本批实际影响：

| 改动类型 | 必要验证 |
|---|---|
| 评价调用、路由或结果调整 | 相关已批准案例/边界、标准身份不串用、涉及入口核心结果一致 |
| 单台/批次协调调整 | 保存数量和类型、快照不可变、执行失败不伪装业务终态 |
| 字段/单位/选项来源调整 | GUI/Excel 实际同源、输入导出、旧模板兼容及必要拒绝用例 |
| 文件/资源/打包路径调整 | 相关资源实际加载、受影响构建产物及启动验证 |
| 纯文档调整 | 入口、链接、状态一致，不运行无关业务全量或压力测试 |

读写或容量机制变化时才复验少量、100、1,000、10,000 行相应场景；容量路径不变沿用已有证据并注明适用 SHA。既有 CI 继续执行，不为同一 Head 手工复制整套 CI；主会话仍独立审阅并按风险运行关键回归，不能只接受子会话自述。分别记录 pass/fail/error/skip/not_run；没有新变化、失败或疑点不重复扩大验证。

每批满足以下五条即结束，不再扩展：

2. 相关现有调用方已实际使用该实现。
3. 被替代定义已删除或成为必要的薄转接。
4. 现有结果、来源、保存、历史行为经相关检查保持正确，现有门禁无新增回归。
5. 新增模块均有当前用途，没有未来功能空壳。
