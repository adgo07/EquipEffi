## 4. 发现的问题与建议

### P1（需处理，中）问题登记未落入根台账，Stage A 出口条件未完成

- 事实：`STANDARD_ISSUES_REGISTER.md` 中检索不到任何 `EQP-STD-GB24500-*` 编号（现有仅为 GB19762/GB20052/GB32030 项）。`ISSUE_REGISTRATION_REQUEST.md` 自述"只是总协调的登记输入，不是正式状态台账"，`HANDOFF.md` 亦列出该协调待办。
- 影响：请求 A（特殊限定值与等级组合输出）、请求 B（初始排放浓度前提证据口径）目前**无稳定编号、无状态、无 Owner 决定记录**，`Standard Issue → Software Decision → Rule / Calculator → Test / Golden` 追踪链断开；按 `docs/standards/README.md` §发现问题时最小流程与 `AGENTS.md` §7，Stage A 的"问题登记"出口条件尚未满足。
- 建议：由总协调在根台账登记 `EQP-STD-GB24500-001`（请求 A）与 `EQP-STD-GB24500-002`（请求 B），状态先 `OPEN`，并在 `ISSUE_REGISTRATION_REQUEST.md` 回填正式编号；在 ID 落定前**不得**把候选处理方式当成已批准解释。

### P2（需处理，中）标准总索引未收录本目录，唯一入口不可达

- 事实：`docs/standards/README.md` §标准总索引目前只有 GB 19762—2025 与 GB 20052—2024 两行，而 `docs/standards/` 下已实际存在 8 个标准目录（含 `gb24500_2020`）。
- 影响：规范要求"每个标准版本一个目录 + 每个目录 README 为唯一入口 + 索引表登记已建档入口"；目前从总入口无法发现 GB 24500 映射，且该缺口对同批 6 个新标准同样存在。
- 建议：由总协调按"标准号/年份、标准名称、设备/Profile、唯一标准入口、当前映射/数据依据、支持状态依据"补行；本轮 6 项可一次性补齐，避免逐会话各自改索引。

### P3（需处理，中）"非冷凝/低位/高位"等整理者术语未被标注为【技术判断】

- 事实：标准原文**从未出现"非冷凝"字样**。映射 §4 的 `室燃天然气非冷凝`、工作簿 `表4 室燃!B6:B8` 的"天然气非冷凝"、"低位/高位"口径，以及 §5 末段"不要求将一份低位效率同时与高位阈值比较"，都属于整理者的解释，但 §4 表格行**未加任何标签**，与 §2/§5 其他段落的【标准】/【技术判断】显式标注做法不一致。
- 依据（本项核验新增的机械证据）：PDF 表格线显示 `锅炉热效率％` 表头是一个**跨两栏的合并单元格**（x=441.3 的分隔线从 227.9 才开始），天然气左右两栏**没有任何列表头文字**；左右栏的区分只能靠脚注 a（"燃气冷凝锅炉额定工况下各能效等级热效率值"）反推。
- 影响：`docs/standards/README.md` 要求"明确标识【标准】、【技术判断】、【实现约定】、【需确认】"。当前写法会让后续读者把它当作标准明文；若将来另一理解（例如左栏为"所有天然气锅炉的通用值"）被采纳，映射与工作簿会有四处静默变更。
- 建议：① §4 给"非冷凝""低位/高位"标【技术判断（由表4脚注a/b推导）】；② 把"表4 天然气左右栏语义与冷凝锅炉高低位判级口径"作为**第三项问题**登记（类型 `TERM`/`AMBIGUITY`，因原文无列表头）；③ §2 第二段（移动式、混烧燃料）中的判断部分与【标准】分开标注。

### P4（需处理，中）建议新增登记的问题候选（现 2 项请求未覆盖）

1. **电加热锅炉的能效等级未规定**：第 1 章把"以电为热源"纳入范围，但表 1～表 4 均无电加热分支（表1/2 燃煤、表3 生物质、表4 室燃天然气/油/煤），而第 4 章规定"各等级工业锅炉……应不低于表 1～表 4 的规定"。结果是电加热锅炉只有 5.2 的 97% 限定值、**无法判定 1/2/3 级**。映射 §4/§5 已正确选择"不捏造 1/2/3 阈值"，但该缺口未登记（类型建议 `MISSING`）。
2. **表内煤种条件重叠**：按条件列字面，`Qnet=18000 kJ/kg、Vdaf=40%` 同时命中"烟煤Ⅱ类（17700≤Qnet≤21000 且 Vdaf>20）"与"褐煤（Qnet≥11500 且 Vdaf>37）"。标准把煤种名作为行标签、Qnet/Vdaf 作为并列条件，未规定条件交叉时如何取舍。映射 §3 已写"煤种名、Qnet 和 Vdaf 条件共同核对"、§6 已列"煤种标签与化验条件矛盾"，但无对应登记项与边界候选（建议 `AMBIGUITY`，并补 1 组 BC）。
3. （与 P3 合并）表 4 天然气左右栏语义与冷凝/非冷凝设备归属。

### P5（建议，低）"一处原格含两个数值"表述不准确

- 事实：`STANDARD_MAPPING.md` §7 写"表4一处原格含两个数值"；`SOURCE_AND_VERIFICATION.md` §结构检查写"右栏同一源格含两个值"。实际为**3 个源格**（每个能效等级 1 格，共 3 格 × 2 值 = 6 个值），CSV 中 `103a(93b)`、`101a(91b)`、`98a(88b)` 三条独立 token 可证。
- 建议：改为"表4 有 3 个源格各含两个数值（低位值与括号高位值）"，避免后续读者低估合并源格数量。

### P6（建议，低）数值复核脚本的执行环境未记录，且默认运行时缺少依赖

- 影响：复核记录要求"必要脚本与人工复核足够"，但环境不可复现会让下一位复核者先卡在依赖上；也不满足"文件 SHA + 方法 + 执行人/日期"最小可复现性要求。
