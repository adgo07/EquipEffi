# <标准编号> 专业解释、疑点和软件决定记录模板

> 复制到`docs/standards/<标准号>_<年份>/STANDARD_INTERPRETATIONS.md`，或在同标准的现有档中新增一个段落。目录规则见[总入口](README.md)。**唯一问题编号/状态维护在根目录`STANDARD_ISSUES_REGISTER.md`**；此文件不复制、替代根台账。

## <EQP-STD-XXX-NNN> — <具体疑点/解释>

- **当前问题状态**：在根台账中查询（本解释文不另设第二状态）。
- **原始证据**：标准编号/年份、正式来源、PDF SHA256、PDF物理页、印刷页、条号/表号/物理行/图像，必要时标注合并单元格；不得用旧JSON反推标准。
- **【标准原文事实】**：能直接从原标准确认的文本、表值、合并单元格及适用边界；逐项保留出处。
- **【专业解释／证据级别】**：技术原理、行业经验、条件及反例；区分已查正式文件/未经核准资料/经验近似。
- **【Owner软件决定】**：决定内容、日期、覆盖的表和分支、输入条件、保守失败状态；未批准时写“未决定”。
- **【未决问题】**：明确尚需哪份标准条款、设计资料/试验报告，不自行补缺；不冒称官方解释。
- **【原解释失效记录】**：写明旧错误（如PDF合并单元格被当空白）、修正证据、影响字段/源格与禁止复活的旧金样。
- **【软件与测试影响】**：对应Mapping、阈值/审计CSV、Golden候选、Calculator/JSON/DB（仅定位，是否实际修改须如实记录）。
- **责任/时间/复核结论**：Owner决定与独立验收分开；没有数字逐格验收不得标“全表已验真”。
- **可复现核验**：结构与数值检查分别写覆盖范围；记录文件SHA、PDF页/源格、XLSX Sheet/实际坐标、提取方法、实际/预期及复核结论。XLSX不按非空值序号定位列；必要时对照原始XML。已撤回发现保留原因，不继续作为修改依据。

原则：只记录实际重要问题，不为每条标准条文立文；在本标准目录集中维护一个解释档，避免大量小文件。
