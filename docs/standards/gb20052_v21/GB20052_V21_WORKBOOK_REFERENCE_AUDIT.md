## 4. 适用方式和警戒线

1. 历史工作簿`标准目录`即使把标准包标`active`，也**不能覆盖**当前仓库治理的`transformer=POST_V1 / NOT_IN_RELEASE_SCOPE`；这是不同时间、不同语义的状态。
2. 旧工作簿有源`transformer.json`展开的数字，不是PDF原表独立双录；不能拿它当第三方“真值”修改本轮映射数值，更不得反向将旧6条/9条/5条补为正确完整路由。
3. Excel 规范化值中78处十进制字面不一致属于Numeric边界待核线索；**不能仅凭工作簿证明现行Evaluator违反Numeric v1**。任何正式变压器Profile的Decimal入口、比较值与精度需在未来实现阶段独立明确和测试。
4. 建议继续按PDF逐表、逐物理分支、逐等级、逐损耗列人工校验；记录“物理页+表号+原值+分支ID+校对人+时间+SHA”；补全表2/15/27/28的Source IDs；D-08/Issue008仍OPEN直到全量数值QA。
5. 本次Owner已批准表1～28合法分支插值的软件口径（D-01/Issue001=RESOLVED），但历史工作簿并未提供插值端点的独立新证据，不能以该批准对缺表值、跨组或外推开绿灯。

## 6. 本轮补核PDF原页造成的纠错

本校对册从JSON平铺得到的历史“校对正确”状态不能验证标准PDF的**合并单元格跨度**。本次直接查看GB20052—2024 PDF物理页7，证实表1在630～2500kVA的Pk栏同时覆盖Yyn0及Dyn11/Yzn11，**与此前映射认为Yyn0空白的结论相反**；前版G09反例作废，CSV从186恢复228条表1候选，35表候选总数1767（未对全表损耗数字验真）。

后续类似情形先看PDF页图，再核表结构与逻辑候选。所有标准问题永久归档于根目录唯一台账与`docs/standards/gb20052_v21/GB20052_STANDARD_INTERPRETATIONS.md`，不据旧JSON自行修补原文。
