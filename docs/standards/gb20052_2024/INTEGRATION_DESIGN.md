## 2. 对现有工作簿的核查结论

当前正式 V6 有18个 Sheet；变压器表为 `TblTransformer=A3:U13`，第3行为表头，第4—13行为预留空行，A—U共21个可见列，V是隐藏的 `condition_key`。十条预留行不是业务行数上限。

当前正式 V6 与 Owner 原始 V6 的变压器列、枚举、表引用和32条公式相同，但两个工作簿的二进制内容不同。正式 V6 已包含获准的泵改动，后续必须从正式 V6 派生。

需要处理的具体差异：

1. F“设备类别”已经有35种对应物理类型及“其他”，包含大部分相数、绕组、调压和用途大类，不能把这些再拆成一排重复必填列。
2. I“短路阻抗(%)”已经存在，但当前为文本留痕，不参与可靠选组；不能直接当成新内核可用的额定阻抗。
3. H“标准条件”中的材质、联结组、热等级可以复用；人工选择4%/6—8%档、普通/特殊低压组及A/B/C组需要退出。实际阻抗和电压应由软件转换成分支。
4. L—Q六个阈值列、R结论列已经预留，不增加另一套输出区。当前这些列没有业务算法；U的长校验公式、V按容量/组别切换的逻辑需要退出或简化。
5. J/K当前数据验证为 `>0`、整数展示；冻结映射允许非负损耗，并要求全值比较。新版变压器验证改为 `>=0`，展示可见小数，不能因显示相同就认定数值相同。
6. 当前正式 V6 文件**没有** `EQUIPEFFI_TEMPLATE_*` / `EQUIPEFFI_SHEET_CONTRACT_*` 身份定义名。Manifest和解析器已经支持这些标记，但此文件实际走唯一登记的 `legacy-structure`。新版必须真正写入新标记，不能只改清单。

## 3. 变压器 Sheet 推荐方案：保留21列，增加3列

**推荐24个可见列。** 保持A—U的坐标及输入/输出分工，在右侧增加V—X三个输入列。H/I复用；旧隐藏V如仍用于下拉辅助，移至Y。不另建一个变压器输入工作簿，不把必要事实藏入万能备注或复杂参数语言。

### 3.2 只增加的三个列

| 新列 | 标题 | 输入设计 | 何时需要 |
|---|---|---|---|
| V | 绕组额定电压(kV) | 固定物理标签，例如 `低=66`、`高=35;低=0.8`；键只允许高/中/低，值为十进制kV，不输入区间或表号 | 泛型110/220kV类别区分表7/8、12/14，表15确定实际LV；新能源29—35确定实际HV/LV；其余只收实际路由必要值 |
| W | 适用条件确认 | 明确选择：`已核实：50Hz且非排除结构`、`非50Hz`、`充气式`、`塔筒变压器`、`机舱变压器`、`未确认` | 正式判定适用性所需；空白是未知，不自动变成50Hz/无排除结构 |
| X | 损耗试验口径 | `规定条件，报告见T列`、`待确认`、`口径不符` | 正式比较双损耗时；查询阈值不要求提前填试验资料 |

W第一项表示用户已明确确认两个事实；其余“非50Hz”或排除结构选项足以证明对应范围外原因。未提供的确切频率或其他事实继续为空，例如选“非50Hz”不能伪造为60Hz。已证明范围外时，不再因未填损耗/报告阻止“不在范围”结论。W是精简输入表示，进入内核后拆成适用性事实及证据，不以中文选项直接决定等级。

X第一项表示输入的P0/Pk已按该产品、该热等级的规定试验方法和参考条件出具，T提供相应报告编号、文件名、链接或可定位资料。它不是要求软件审核报告全文，也不要求用户重复抄已经在报告中明确的温度数值。对需要证明试验口径却完全没有依据的输入，返回 `TEST_CONDITION_UNVERIFIED`；不把一般追溯信息欠缺一概当计算失败。表1按其规定试验口径，不额外规定一律75℃；其他表的75℃及干式B100/F120/H145℃按映射§22执行。自动温度换算继续延期。

不用顶行“一次确认全表”代替W/X。混合设备或新增行容易被套上并未核实的频率/试验声明；逐行有限枚举可复制填充，只有用户已确认的行才获得该事实，不增加批量声明继承机制。

### 3.3 复用F/H/I，减少实际填写量

- **F已有完整物理型式时直接拆解。** 表20—24的F选项明确包含中压110/220kV和调压位置；表8已含低压35kV，表14已含低压66kV。用户明确选中后记录来源F，不重复要求V抄同一事实。若V另填冲突值，提示输入矛盾，不偷偷改用另一张表。
- **泛型F不能证明排除了特殊电压。** 表7/12泛型类别仍需要真实LV，不能把没选专用类别当成“已确认LV不是35/66”。表15也必须按实际LV区分普通与66/69组；匹配专用表/分支后，容量不覆盖时不回退泛型表。
- **新能源F仅写允许范围，不是设备实值。** V填写实际HV/LV；H选择光伏、风电、储能。干式新能源H用“用途×B/F/H”九种组合，油浸式三种用途，不把F放大三倍、不建立三份阈值数据。
- **表1/2的H保留材质＋联结或热等级。** 表2在630kVA有两套候选损耗行，I填真实额定阻抗，例如4.2；软件按已批准±10%选组。其他唯一损耗分支容量不新增无关阻抗必填要求。
- **表27/28的I是完整三元。** 例：`高—中=12.9;高—低=44;中—低=29`。只支持这类固定标签结构，解析后是三个独立Decimal字段；空一项不猜、A/B/C不能当输入。与电压列相同，允许中英文分号及去除外围空白，重复键或无法识别的量提示具体单元格。
- **表9/13的升/降压如保留，仅作可选技术条件。** 它不改变损耗阈值，缺少时不阻断已经唯一确定的等级。
- 可选实测阻抗、一般备注不成为新列或必填；不能把实测阻抗自动写进额定阻抗字段。`其他`或`未确认`不触发从型号、安装位置、备注进行智能猜测。

| 当前旧软件 | 新V6.1 | 不能保证读取 | 不支持 | 当前解析器会拒绝未知版本/修订，需升级软件；不回补旧客户端 |
| 新软件 | 未来未知版本、身份残缺/冲突、必要结构损坏 | 不强行猜读 | 不强行猜读 | 给模板错误及更新/重新取得模板提示，不伪装成设备“无法判定” |

本次**不维护两套可计算的变压器Sheet适配器**。旧V6没有足够适用性/试验口径输入；兼容承诺是旧泵仍可用、旧变压器数据保留，不是旧变压器可以自动正式判级。这样也避免长期维护人工组选组与真实参数选组两条业务路径。

现有代码依据：`infrastructure/excel/template_resource.py::_resolve_v6_identity_from_names()`精确匹配模板ID与版本并检查Sheet修订。泵Sheet不变，不足以让旧软件接受新工作簿。

### 4.3 旧变压器数据怎么带到新版

最小流程是下载V6.1新副本，复制可确认的输入，再补缺失事实；不开发通用迁移向导，不覆盖原文件。

| 旧内容 | 新版处理 |
|---|---|
| B—G基础信息/明确类别/容量、J/K双损耗、S/T资料 | 按对应列复制；仍需由X说明损耗试验口径 |
| H材质、联结、热等级 | 只保留可无歧义映射的真实条件；新能源补具体用途 |
| H的4%/6—8%、A/B/C、普通/特殊低压组 | 不转成额定阻抗或电压；可在T保留“旧表记录”，用户核实后填I/V |
| I旧“短路阻抗”文本 | 先确认是额定/设计值还是实测；角色未知不直接认作额定值 |
| 新V/W/X | 缺失留空；用户补充，不能预填“已核实” |
| L—R/U旧结果与公式 | 不复制为新版业务输入；由新内核重新分析后写出 |

泵输入按原坐标复制即可，泵Sheet结构不改。历史Record保持原快照，模板迁移不追溯改写已存记录。旧文件里其他未接入Sheet的输入和附件继续保留；不能因为旧模板升级就丢掉其他设备资料。

### 4.4 “泵Sheet不改”的实际保护范围

保护当前正式V6的泵值/公式、表头、单位、列顺序、有效样式、保护、数据验证、合并、附件及相关关系，`TblPump=A3:AA103`和 `pump-input.v1`保持。新工作簿整体SHA必然变化，不以整体SHA相同替代Sheet兼容。

同时保护共享配置依赖：`EV_PUMP_CATEGORY='配置'!$AE$2:$AE$11`、`EV_SUCTION='配置'!$AI$2:$AI$3`、FieldDictionary泵区 `A62:P88`，以及实际引用的名称、值与顺序。变压器扩展配置在独立区域追加，不在字典前部插行造成全表位移。共享strings/styles如序号变化，比较解析后的有效内容，不能只检查一个sheet XML文件名。

新版仅修改变压器及其必要配置、模板身份、模板说明/注意事项。说明区中旧“不适用/资料待完善”等文案可同步到已批准术语，这不是修改泵Sheet或泵判定。第三步复用现有模板检查工具核实这些边界，不建立新的全仓哈希门禁。

## 5. 从冻结双文件派生运行数据

主映射提供规则，工作簿提供表值，二者共同驱动一个版本化变压器数据包。运行时使用派生包，GUI/Excel不读取各自维护的阈值副本。原标准PDF及校对工作簿无需打进正式程序。

### 5.1 正确来源及派生边界

校对工作簿共有40个Sheet，**只从“表01”—“表35”的逐表视图提取冻结数值**。“标准数据平铺”是旧JSON的历史底稿，“分类与枚举”等也含历史状态，不得整本扫描混入当前真值。

只读统计：35表合计589条分支容量行，G—L每行6个损耗值，共3534个数值单元格；按每级一条记录展开则1767条。建议运行结构保留589行及三级P0/Pk，减少不必要展开。这些数量用于核对派生完整性，**不代表本次重新完成原PDF逐格审核**。

派生步骤：锁定双文件SHA → 按真实Sheet/坐标读取原始十进制文本 → 规范物理分支/单位/来源 → 生成带版本和哈希的运行包 → 与冻结源逐值核对 → 独立候选验证选表和判级。派生脚本属于构建工具，不是每次运行扫描Excel；派生结果可再生成，不作为另一套手工维护表。

### 5.2 最小运行结构

| 对象 | 保留内容 |
|---|---|
| 包身份 | 标准号/年份、主映射修订及SHA、35表SHA、生成器/运行数据schema版本、包版本/哈希 |
| 表路由 | 用途、标称电压、介质、相数、绕组、调压、自耦、必要绕组电压及调压位置；源条款/表题 |
| 损耗分支 | 铁心、联结、热级、特殊低压或真实阻抗组；完整物理分支ID，不能因损耗相同合并 |
| 容量行 | 额定容量、三级P0/Pk、源单位/参考温度、原值状态、源行ID |
| 技术条件 | 技术阻抗、方向等；与损耗阈值分开，源表未列的量为null |
| 来源 | Sheet、实际G—L坐标、源行ID、单位M/N、页码定位Q、标准原物理合并格关系；不能以非空元素下标代替坐标 |

表1的“Pk合并原格共享”是物理源格说明，不能被当成新损耗分支，不能因此禁止500→630插值。表2需保留4%容量30—630和6—8%容量630—2500两条连续分支，630有真实重复容量。表27/28即使B/C同损耗，也保留各自物理分支和来源。表23/24没有列出的HL/ML阻抗保持null，不补0、不从邻表补值。

软件实现只维护一份输入/指标定义，供Qt、Excel字段适配和结果说明引用。业务条件在领域/应用契约，列字母/表头/布局在模板契约；不把两种职责混成Excel配置驱动算法。

## 6. 正式判定顺序与数值规则

### 6.1 直接执行已批准映射，不重新解释标准

1. 按映射先核对输入与适用性。有明确排除证据给“不在范围”；必要事实未知给“无法判定”。不因无关字段缺失推翻已确定的范围结论。
2. 由明确物理型式和实际电压选表；表8优先于7，14优先于12，表15先选普通/66/69分支，再核对该分支容量。不得容量不够时回退有利表。
3. 仅在损耗分支需要时使用额定阻抗。批准的软件选组规则：点v匹配 `[0.9v,1.1v]`；范围[a,b]匹配 `[0.9a,1.1b]`，包含端点；27/28三个分量共同匹配。不使用“HM+ML≈HL”代替三元。
4. 全部不匹配为 `IMPEDANCE_NO_MATCH`；多个命中且**本容量的全部六阈值一致**，可判级并保存全部分支/来源；不同则 `BRANCH_AMBIGUOUS`，不可取首行。此处按映射后续批准§28/31执行，不采用早期“任何多命中都不能判”的历史段落。
5. 唯一表/分支的容量闭区间外，给“不在范围 / OUTSIDE_TABLE_CAPACITY_RANGE”，说明这是软件批准的表列容量覆盖边界。范围内缺真实值或没有合法端点，给“无法判定”，不补0、不取最近档。
6. 所有35表均按批准D-01，在同表、同完整损耗分支的相邻真实容量之间分别插值六个阈值；不跨表、跨联结、跨热级、跨阻抗组，不外推。记录端点，不创造“标准原表新增容量行”。
7. 正式判级需有效P0、Pk和可信试验口径；1级→2级→3级逐级检查 `P0<=该级P0限值 AND Pk<=该级Pk限值`。等号通过，不做总损耗相加或互相补偿。均不满足3级为“未达3级”。缺一项可返回已知阈值，但不能给正式等级。

`INVALID_INPUT`、当前软件未支持、标准包/执行异常、保存失败分别处理，不填成六种业务结论。业务无法判定的原因、输入错误及程序错误在结果模型中分开，Excel R只写合法业务结论，U写相应说明；错误行不伪造等级或旧阈值。

### 6.2 变压器独立 Numeric Profile（本轮设计提案）

| 项目 | 方案 |
|---|---|
| `numeric_profile_id` | `EQUIPEFFI_TRANSFORMER_GB20052_DECIMAL50_V1` |
| `numeric_contract_version` | 已锁定 Numeric Contract v1 |
| 表示/入口 | 精确十进制文本、Decimal、精确整数；未声明float、NaN、Infinity拒绝 |
| 工作精度/舍入 | precision=50，`ROUND_HALF_EVEN`，显式局部上下文 |
| 单位 | 内部损耗W，源kW精确×1000；容量kVA、电压kV、阻抗以百分数数值表示 |
| 正式比较 | 使用完整工作值；等号包含；不加等级epsilon、不做ROUND6或预比较显示修约 |
| 插值顺序 | `P1 + ((S-S1)*(P2-P1))/(S2-S1)`，全部运算消费本Profile |
| 显式业务修约 | 无；工作舍入与展示舍入分别记录语义 |
| 超越函数 | `not_applicable`，不引入泵的PUMP-RP过程 |
| 容差 | 只有已批准的阻抗选组±10%；不扩大到损耗阈值 |
| 显示 | 沿用产品展示规则；原表精度可保留，派生数值适度展示；显示值不回流比较 |

选择50位是本标准的实现设计，**不是国标要求、中央默认或最小精度证明**；不复用泵Profile ID，也不改变泵上下文。循环小数按该Profile及运算顺序可复现。独立有理数核对器用于测试期望分析，生产不因此引入第二套求值器。

Excel继续复用现有OOXML数值读取：从文件实际保存的十进制文本转Decimal，不先经float。不能恢复Excel/WPS保存之前已经丢失的精度；特别高精度边界样本用文本数值保留。I中的4.2表示4.2%，不以Excel百分比格式的0.042默默代替；金额/日期/错误类型不当损耗读取。本版变压器输入参数不接受依赖缓存的公式结果，明确提示粘贴数值；结果列和展示公式不进入业务输入，泵既有输入行为不变。

## 7. 软件接入：两个内核，共用应用边界与结果

### 7.1 最小结构

保留 `CentrifugalPumpAnalysisService` 和泵算法；新增类型明确的 `TransformerAnalysisRequest/Result`、`TransformerAnalysisService` 及唯一变压器Calculator。Qt与Excel适配生成同一个变压器请求，服务返回同一结果。未来Word/其他平台消费同一结果契约及快照，本轮不新增Word或多端实现。

共同消费者只需要一个小型结果Protocol和设备入口映射：标准/设备、状态/等级、可保存资格、指标、阈值、原因、来源与版本。请求不强制继承拥有全部设备字段的父类；选表/插值/判级保留在各自领域，不建设通用规则DSL、动态插件系统或平台重构。

内部结果至少承载：规范输入与来源；选表/全部命中分支；六阈值及单位；P0/Pk比较和整体等级；exact/interpolated及端点；缺失/冲突/非阻断信息；包、规则、计算器、Numeric Profile、结果契约身份。稳定指标ID例如 `transformer.no_load_loss`、`transformer.load_loss`，不借用 `pump.*` 指标。展示层只投影，不再计算。

### 7.2 一次工作簿，一次输出，一条批次记录

工作簿协调服务识别版本和参与Sheet → 各Sheet适配器读取 → 分别调用泵/变压器 `evaluate()` → 按 `(sheet_id,row_number)` 收集结果 → 一次生成全部OOXML补丁 → 新文件成功提交 → 保存一条 `batch_record`。

不为每个Sheet各建一个批次，不为每行调用单台自动留档。两张Sheet同为第6行不能串写；一行合法业务无法判定不阻止其他行完成。输出不覆盖输入，模板结构错误先明确报错，执行/写文件/保存失败分别反馈。批次汇总同时列出处理、空行、输入错误、程序错误及保留未处理Sheet；旧结果列不作为再次输入。

复用成熟的OOXML补丁、原子提交和输入保真能力，一次读取/写出同一ZIP，不串行执行两次“另存为”。新增变压器也按语义有效行读取，支持超出原Table预设十行的数据，不增加逐Sheet扩容设置。

### 7.3 历史记录无需数据库迁移

现有 `RecordSnapshot` 的输入/结果/来源JSON及规则、数据、计算器、Profile身份足以容纳变压器。保持数据库表和迁移文件不变。

批次摘要使用新 `summary_schema_version`，增加 `sheets[]`，每Sheet记录契约、标准、数量/结论汇总、问题和实际计算版本；旧摘要只在内存中适配显示，不写回。多标准批次顶层不再适用的单值字段（`standard_code/device_type/sheet_name/canonical_version/numeric_profile_id`等）用空字符串 `""`，不能传 `None` 或 SQL `NULL`，因为现有字段为字符串且数据库列 `NOT NULL`；由 `sheets[]`提供真实身份，不能继续写泵或拼出一个不存在的Profile。单标准批次保留其真实单值，普通页面对混合批次显示“离心泵、变压器”。

记录详情始终读保存快照，不按当前包重算；历史查询从泵服务中提取为确实共用的小型查询服务，不复制第二套Repository或记录系统。源字段不足/未执行Calculator的行只记录实际用到的输入契约身份，不虚构算法已执行的证据。

## 8. 验证设计：重点验证业务边界，避免重复验收

### 8.1 第二步内核验证
