## 2. 对现有工作簿的核查结论

当前正式 V6 有18个 Sheet；变压器表为 `TblTransformer=A3:U13`，第3行为表头，第4—13行为预留空行，A—U共21个可见列，V是隐藏的 `condition_key`。下一版设计为 `TblTransformer=A3:Y103`，预置100条数据行；100行不是业务容量上限，目标是经可靠的表格扩展机制支持至少10,000条数据行，不要求用户逐Sheet配置或手工扩容。

当前正式 V6 与 Owner 原始 V6 的变压器列、枚举、表引用和32条公式相同，但两个工作簿的二进制内容不同。正式 V6 已包含获准的泵改动，后续必须从正式 V6 派生。

需要处理的具体差异：

1. F“设备类别”已有35种对应物理类型和其他类别，可通过明确受控选项承载适用性事实；不得从型号等字段猜测，也不再增加独立适用性确认列。
2. I“短路阻抗(%)”已经存在，但当前为文本留痕，不参与可靠选组；不能直接当成新内核可用的额定阻抗。
3. H“标准条件”中的材质、联结组、热等级可以复用；人工选择4%/6—8%档、普通/特殊低压组及A/B/C组需要退出。实际阻抗和电压应由软件转换成分支。
4. L—Q六个阈值列、R结论列已经预留，不增加另一套输出区。当前这些列没有业务算法；U的长校验公式、V按容量/组别切换的逻辑需要退出或简化。
5. J/K当前数据验证为 `>0`、整数展示；冻结映射允许非负损耗，并要求全值比较。新版变压器验证改为 `>=0`，展示可见小数，不能因显示相同就认定数值相同。
6. 当前正式 V6 文件**没有** `EQUIPEFFI_TEMPLATE_*` / `EQUIPEFFI_SHEET_CONTRACT_*` 身份定义名。Manifest和解析器已经支持这些标记，但此文件实际走唯一登记的 `legacy-structure`。新版必须真正写入新标记，不能只改清单。

## 3. 变压器 Sheet 已确认方案：保留21列，增加4列

**最终为25个可见列。** A—U及坐标保持不变；在右侧新增V—Y四列。F的受控设备类别明确承载用途和适用性路由事实；H记录实际物理条件；I、X、Y分别承载独立数值阻抗，不允许在单元格内拼接多个参数。J/K固定使用W，没有可选单位列。旧隐藏V `condition_key` 退出；如模板交互需要辅助清单，辅助数据另置隐藏Z及之后，不能继续承载选表或损耗组真值。

### 3.2 只增加的四个列

| 新列 | 标题 | 输入设计 | 何时需要 |
|---|---|---|---|
| V | 高压额定电压(kV) | 单个十进制数值 | 选表或边界核查需要实际高压绕组电压时 |
| W | 低压额定电压(kV) | 单个十进制数值 | 特殊低压分支或新能源实际绕组范围核查需要时 |
| X | 额定阻抗高—低(%) | 单个十进制数值；不使用带标签拼接文本 | 三绕组且规则需要高低阻抗时；表27/28必须与I/Y共同组成三元 |
| Y | 额定阻抗中—低(%) | 单个十进制数值；不使用带标签拼接文本 | 三绕组且规则需要中低阻抗时；表27/28必须与I/X共同组成三元 |

F是单元格级受控类别选择，选项必须明确映射到结构化事实，不能从型号、安装位置、备注或其他参数推测。选项表达普通/新能源大类、介质、电压类别、相数、绕组数、自耦、调压方式和必要分接位置；表20—24所需中压及调压位置由明确的F类别选项承载。F的“其他类别”显示“不在范围”；“不确定类别”显示“无法判定”。两项不是非法输入或待补交独立适用性确认；不确定类别未计算，不因此伪造正式判级或保存资格。V/W用于需要实际高、低压额定值的路由核查；未知或缺失必要事实仍不得猜测。

F/H下拉及联动只提供受控输入，不在Excel中决定标准、阈值或等级。H选择实际铁心、联结和适用热等级；新能源具体用途亦由H明确。任何字段都不让用户选择A/B/C或其他人工损耗组。

D-06只继续延期自动温度换算，不新增温度确认列、试验口径确认列或报告门禁。J/K以W输入，软件直接使用输入值按选定标准限值比较，不做温度换算；T为可选备注/报告引用，不是必填。运行数据保留源表的单位与参考温度以供内部追溯，但这些元数据不转化为用户确认门槛。

### 3.3 复用F/H/I，减少实际填写量

- **F类别是明确的路由事实。** 表20—24的F选项明确包含中压110/220kV、绕组/自耦及调压位置；表8、14由明确类别选择表达，表15的普通/66/69kV损耗分支由W中的实际低压额定电压判别。V/W在映射要求真实高/低压绕组电压时补充单值输入；类别选项和实际电压冲突时提示输入矛盾，不偷偷改用另一张表。
- **新能源F区分型式，H明确具体用途，V/W记录实际电压。** 油浸H提供光伏/风电/储能3项，干式H提供用途×B/F/H的9项有限组合；不将F的7类扩大三倍。需要HV/LV实际值时分别填V/W，不从电压猜用途，也不把H扩成手选损耗组。
- **表1/2的H保留材质＋联结或热等级。** 表2仅在630kVA有两套候选损耗行；此时I填真实额定阻抗，例如4.2，软件按已批准±10%选组。非630kVA是否填写I都按容量唯一损耗分支判级；提供的阻抗只随输入记录留存，不参与选组、范围筛选或判级。
- **表27/28使用三格完整阻抗三元组。** I=高—中、X=高—低、Y=中—低，三格分别只接受一个数值百分数；任一需要项缺失就无法选组。不解析分号、键值串或其他拼接文本；A/B/C不能作为输入组别。表23/24仅列高—中阻抗，作为选填技术输入留痕，缺少时不阻断判级；冻结映射§32明确其不影响损耗阈值，不要求原表未列的高低/中低阻抗。其余表不要求无关阻抗。
- **表9/13的升/降压如保留，仅作可选技术条件。** 它不改变损耗阈值，缺少时不阻断已经唯一确定的等级。
- 可选实测阻抗、一般备注不成为新列或必填；不能把实测阻抗自动写进额定阻抗字段。“其他类别”映射为 `OUT_OF_SCOPE`，“不确定类别”映射为 `UNABLE_TO_JUDGE`；均不触发从型号、安装位置、备注进行智能猜测。

| 其他设备Sheet | `v6-preserved` | 保持，不因增加变压器而承诺已支持 |
| 规则、运行数据、计算器、Numeric Profile | 与模板版本各自独立 | 指向冻结V2.1及派生包/实现版本，不用“V6.1”代替业务版本 |

Manifest同时登记旧/新两个模板，默认下载选择明确的 `(template_id, template_version)`，不以数组第一项或仅家族ID碰运气。旧V6保留唯一 `legacy_import_compatibility=true` 入口；新版显式打标且该项为false。对填入用户数据后的文件，文件SHA用于来源记录，不能要求它等于空白模板SHA。

现有代码依据：`infrastructure/excel/template_resource.py::_resolve_v6_identity_from_names()`精确匹配模板ID与版本并检查Sheet修订。泵Sheet不变，不足以让旧软件接受新工作簿。

### 4.3 旧变压器数据怎么带到新版

最小流程是下载V6.1新副本，复制可确认的输入，再补缺失事实；不开发通用迁移向导，不覆盖原文件。

| 旧内容 | 新版处理 |
|---|---|
| B—G基础信息/明确类别/容量、J/K双损耗、S/T资料 | 按对应列复制；报告和备注保持可选，不要求新增试验确认 |
| H材质、联结、热等级 | 只保留可无歧义映射的真实条件；新能源补具体用途 |
| H的4%/6—8%、A/B/C、普通/特殊低压组 | 不转成额定阻抗或电压；可在T保留“旧表记录”，用户核实后填I/X/Y或V/W |
| I旧“短路阻抗”文本 | 先确认是额定/设计值还是实测；角色未知不直接认作额定值 |
| 新V—Y | 缺失留空；需要的真实电压或额定阻抗由用户逐格补入单值，不解析拼接文本 |
| L—R/U旧结果与公式 | 不复制为新版业务输入；由新内核重新分析后写出 |

泵输入按原坐标复制即可，泵Sheet结构不改。历史Record保持原快照，模板迁移不追溯改写已存记录。旧文件里其他未接入Sheet的输入和附件继续保留；不能因为旧模板升级就丢掉其他设备资料。

### 4.4 “泵Sheet不改”的实际保护范围

保护当前正式V6的泵值/公式、表头、单位、列顺序、有效样式、保护、数据验证、合并、附件及相关关系，`TblPump=A3:AA103`和 `pump-input.v1`保持。新工作簿整体SHA必然变化，不以整体SHA相同替代Sheet兼容。

同时保护共享配置依赖：`EV_PUMP_CATEGORY='配置'!$AE$2:$AE$11`、`EV_SUCTION='配置'!$AI$2:$AI$3`、FieldDictionary泵区 `A62:P88`，以及实际引用的名称、值与顺序。变压器扩展配置在独立区域追加，不在字典前部插行造成全表位移。共享strings/styles如序号变化，比较解析后的有效内容，不能只检查一个sheet XML文件名。

新版仅修改变压器及其必要配置、模板身份、模板说明/注意事项。说明区中旧“不适用/资料待完善”等文案可同步到已批准术语，这不是修改泵Sheet或泵判定。第三步复用现有模板检查工具核实这些边界，不建立新的全仓哈希门禁。

## 5. 从冻结双文件派生运行数据

主映射提供规则，工作簿提供表值，二者共同驱动一个版本化变压器数据包。运行时使用派生包，GUI/Excel不读取各自维护的阈值副本。原标准PDF及校对工作簿无需打进正式程序。

### 5.1 正确来源及派生边界

校对工作簿共有40个Sheet，**只从“表01”—“表35”的逐表视图提取冻结数值**。“标准数据平铺”是旧JSON的历史底稿，“分类与枚举”等也含历史状态，不得整本扫描混入当前真值。

只读统计：35表合计589条分支容量行，G—L每行6个损耗值，共3534个数值单元格；按每级一条记录展开则1767条。建议运行结构保留589行及三级P0/Pk，减少不必要展开。这些数量用于核对派生完整性，**不代表本次重新完成原PDF逐格审核**。

派生步骤：锁定双文件SHA → 按真实Sheet/坐标读取原始十进制文本 → 规范物理分支/单位/来源 → 生成带版本和哈希的运行包 → 与冻结源逐值核对 → 独立候选验证选表和判级。生成器确定性地产生路由、受控F/H选项映射和运行数值；标准工作簿以kW表达的源限值按Decimal精确换算成内部W，同时保留原始值、原单位、参考温度、真实坐标和来源ID。J/K输入契约则始终是W。派生脚本属于构建工具，不是每次运行扫描Excel；派生结果可再生成，不作为另一套手工维护表。

### 5.2 最小运行结构

| 对象 | 保留内容 |
|---|---|
| 包身份 | 标准号/年份、主映射修订及SHA、35表SHA、生成器/运行数据schema版本、包版本/哈希 |
| 表路由 | F受控类别映射的用途、标称电压类别、介质、相数、绕组、调压、自耦、中压/必要分接位置；V/W承载条件所需的实际高/低压额定值；源条款/表题 |
| 损耗分支 | 铁心、联结、热级、特殊低压或真实阻抗组；完整物理分支ID，不能因损耗相同合并 |
| 容量行 | 额定容量、三级P0/Pk的W规范值、源单位/参考温度、原值状态、源行ID |
| 技术条件 | 技术阻抗、方向等；与损耗阈值分开，源表未列的量为null |
| 来源 | Sheet、实际G—L坐标、源行ID、单位M/N、页码定位Q、标准原物理合并格关系；不能以非空元素下标代替坐标 |

表1的“Pk合并原格共享”是物理源格说明，不能被当成新损耗分支，不能因此禁止500→630插值。表2需保留4%容量30—630和6—8%容量630—2500两条连续分支，630有真实重复容量。表27/28即使B/C同损耗，也保留各自物理分支和来源。表23/24没有列出的HL/ML阻抗保持null，不补0、不从邻表补值。

软件实现只维护一份输入/指标定义，供Qt、Excel字段适配和结果说明引用。业务条件在领域/应用契约，列字母/表头/布局在模板契约；不把两种职责混成Excel配置驱动算法。

## 6. 正式判定顺序与数值规则

### 6.1 直接执行已批准映射，不重新解释标准

1. 先按F的明确受控类别核对适用性和路由。“其他类别”给 `OUT_OF_SCOPE` /“不在范围”，“不确定类别”给 `UNABLE_TO_JUDGE` /“无法判定”；不额外要求独立适用性确认。必要路由事实仍缺失时给“无法判定”，不因无关字段缺失推翻已确定的范围结论。
2. 由明确物理型式和实际电压选表；表8优先于7，14优先于12，表15先选普通/66/69分支，再核对该分支容量。不得容量不够时回退有利表。
3. 仅在损耗分支需要时使用额定阻抗。批准的软件选组规则：点v匹配 `[0.9v,1.1v]`；范围[a,b]匹配 `[0.9a,1.1b]`，包含端点；27/28三个分量共同匹配。不使用“HM+ML≈HL”代替三元。
4. 全部不匹配为 `IMPEDANCE_NO_MATCH`；多个命中且**本容量的全部六阈值一致**，可判级并保存全部分支/来源；不同则 `BRANCH_AMBIGUOUS`，不可取首行。此处按映射后续批准§28/31执行，不采用早期“任何多命中都不能判”的历史段落。
5. 唯一表/分支的容量闭区间外，给“不在范围 / OUTSIDE_TABLE_CAPACITY_RANGE”，说明这是软件批准的表列容量覆盖边界。范围内缺真实值或没有合法端点，给“无法判定”，不补0、不取最近档。
6. 所有35表均按批准D-01，在同表、同完整损耗分支的相邻真实容量之间分别插值六个阈值；不跨表、跨联结、跨热级、跨阻抗组，不外推。记录端点，不创造“标准原表新增容量行”。
7. 正式判级需有效P0、Pk；按J/K录入的W值直接和限值比较，不引入报告/试验口径确认门禁，也不做自动温度换算。1级→2级→3级逐级检查 `P0<=该级P0限值 AND Pk<=该级Pk限值`。等号通过，不做总损耗相加或互相补偿。均不满足3级为“未达3级”。缺一项可返回已知阈值，但不能给正式等级。

`INVALID_INPUT`、当前软件未支持、标准包/执行异常、保存失败分别处理，不填成六种业务结论。业务无法判定的原因、输入错误及程序错误在结果模型中分开，Excel R只写合法业务结论，U写相应说明；错误行不伪造等级或旧阈值。

### 6.2 变压器独立 Numeric Profile（本轮设计提案）

| 项目 | 方案 |
|---|---|
| `numeric_profile_id` | 沿用变压器独立Numeric方案 `EQUIPEFFI_TRANSFORMER_GB20052_DECIMAL50_V1`，不借用泵Profile |
| `numeric_contract_version` | 已锁定 Numeric Contract v1 |
| 表示/入口 | 精确十进制文本、Decimal、精确整数；未声明float、NaN、Infinity拒绝 |
| 工作精度/舍入 | precision=50，`ROUND_HALF_EVEN`，显式局部上下文 |
| 单位 | 内部损耗W，源kW精确×1000；容量kVA、电压kV、阻抗以百分数数值表示 |
| 正式比较 | 使用完整工作值；等号包含；不加等级epsilon、不做ROUND6或预比较显示修约 |
| 插值顺序 | `P1 + ((S-S1)*(P2-P1))/(S2-S1)`，全部运算消费本Profile |
| 显式业务修约 | 无；工作舍入与展示舍入分别记录语义 |
| 超越函数 | `not_applicable`，不引入泵的PUMP-RP过程 |
| 容差 | 只有已批准的阻抗选组±10%；不扩大到损耗阈值 |
| 显示 | 沿用产品展示规则；原表精度可保留，派生数值适度展示；显示值不回流比较 |

变压器采用独立Decimal50语义，**不是国标要求、中央默认或最小精度证明**；不复用泵Profile ID，也不改变泵上下文。实现复用现有十进制运行基础，但必须显式使用该变压器Profile及局部上下文。循环小数按既定Profile及运算顺序可复现。独立有理数核对器用于测试期望分析，生产不因此引入第二套求值器。

Excel继续复用现有OOXML数值读取：从文件实际保存的十进制文本转Decimal，不先经float。不能恢复Excel/WPS保存之前已经丢失的精度；特别高精度边界样本用文本数值保留。I/X/Y中的阻抗均为百分数数值；V/W为单值kV；J/K的单位固定W，不存在单位列或单位选项。金额/日期/错误类型不当损耗读取。本版变压器输入参数不接受依赖缓存的公式结果，明确提示粘贴数值；结果列和展示公式不进入业务输入，泵既有输入行为不变。

## 7. 软件接入：两个内核，共用应用边界与结果

### 7.1 最小结构

保留 `CentrifugalPumpAnalysisService` 和泵算法；新增类型明确的 `TransformerAnalysisRequest/Result`、`TransformerAnalysisService` 及唯一变压器Calculator。Qt与Excel适配生成同一个变压器请求，服务返回同一结果。未来Word/其他平台消费同一结果契约及快照，本轮不新增Word或多端实现。

共同消费者只需要一个小型结果Protocol和设备入口映射：标准/设备、状态/等级、可保存资格、指标、阈值、原因、来源与版本。请求不强制继承拥有全部设备字段的父类；选表/插值/判级保留在各自领域，不建设通用规则DSL、动态插件系统或平台重构。

内部结果至少承载：规范输入与来源；选表/全部命中分支；六阈值及单位；P0/Pk比较和整体等级；exact/interpolated及端点；缺失/冲突/非阻断信息；包、规则、计算器、Numeric Profile、结果契约身份。稳定指标ID例如 `transformer.no_load_loss`、`transformer.load_loss`，不借用 `pump.*` 指标。展示层只投影，不再计算。

### 7.2 一次工作簿，一次输出，一条批次记录

工作簿协调服务识别版本和参与Sheet → 各Sheet适配器读取 → 分别调用泵/变压器 `evaluate()` → 按 `(sheet_id,row_number)` 收集结果 → 一次生成全部OOXML补丁 → 新文件成功提交 → 保存一条 `batch_record`。

不为每个Sheet各建一个批次，不为每行调用单台自动留档。两张Sheet同为第6行不能串写；一行合法业务无法判定不阻止其他行完成。输出不覆盖输入，模板结构错误先明确报错，执行/写文件/保存失败分别反馈。批次汇总同时列出处理、空行、输入错误、程序错误及保留未处理Sheet；旧结果列不作为再次输入。

复用成熟的OOXML补丁、原子提交和输入保真能力，一次读取/写出同一ZIP，不串行执行两次“另存为”。变压器Sheet预置100条数据行，并以Excel Table自动扩展或经实测可靠的等价机制支持至少10,000条数据行；按语义有效行读取，不增加逐Sheet容量设置。

### 7.3 历史记录无需数据库迁移

现有 `RecordSnapshot` 的输入/结果/来源JSON及规则、数据、计算器、Profile身份足以容纳变压器。保持数据库表和迁移文件不变。

一个工作簿（无论含一个还是多个已接通Sheet）只写一条 `batch_record`；数据库和migration文件不改。多标准批次在现有 `summary_json` 中写 `schema_version: 2` 和 `sheets[]`；顶层 `standard_code/device_type/sheet_name/canonical_version/numeric_profile_id` 使用 MULTI 哨兵，真实身份及逐Sheet统计写入 `sheets[]`。单标准批次保留原顶层值。每个Sheet项使用标准登记中的完整稳定标准号（如 GB 19762-2025、GB 20052-2024）、实际设备类型/Profile ID、契约、数量/结论汇总、问题和计算版本；不使用无年份标准号，也不以 `pump_water` 代表整张离心泵Sheet。旧摘要只在内存中适配显示，不写回。UI把 MULTI 映射为“多标准/多设备”，显示各Sheet中文设备名称，不直接展示占位值；不新造数据库列或记录类型。

```json
{
  "schema_version": 2,
  "standard_code": "MULTI",
  "device_type": "MULTI",
  "sheet_name": "MULTI",
  "canonical_version": "MULTI",
```

### B.4 表27/28允许B/C同阈值多命中

额定三元 `(HM=12.9,HL=44,ML=29)%` 同时匹配B/C：B的HM12扩展10.8—13.2，表27C的14—22扩展12.6—24.2，表28C的14—15扩展12.6—16.5；其他两分量也共同匹配。

- 表28的120000kVA：`G5:L5=G6:L6` 为 `28,225,33,225,40,238` kW，源行ID为 `GB20052-R000580/R000585`。P0=28、Pk=220为1级，并保留两行来源；A组Pk1/2=212、Pk3=223，同样损耗为3级。
