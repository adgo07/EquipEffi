# 标准档案总入口与目录规范

> 适用于EquipEffi后续所有设备类型与标准。**一个根问题台账＋各标准的Mapping/解释档**，轻量维护，不新增CI、数据库或双重审批。

## 当前映射使用边界

2026-10-19 Owner 已明确变压器映射完成（见 AGENTS 的冻结资产约束），其主映射与35表工作簿继续成套冻结保护；这不等同于软件已接入或 SUPPORTED。当前正式软件范围仍为 GB 19762—2025 离心泵，Profile 状态以 V1_SCOPE.md 为唯一权威。

其他标准逐项按其唯一入口的核验和批准证据处理，不因存在文件、运行包或历史 PR 就推定可用。新增标准接入沿用既有 Stage A→B→C→D；2026-10-23 Owner已明确下一版本纳入变压器并先开展Stage B，见[接入设计](gb20052_2024/INTEGRATION_DESIGN.md)。此前简化阶段的暂缓不再阻止该项已授权设计；其他标准不自动扩入范围。映射状态、资料入库与软件正式支持须分别记录，不新建可用状态台账或重复审批。

本轮必须区分：变压器V2.1双文件已冻结；当前正式统一V6的离心泵Sheet已确定不修改；用户输入工作簿中的变压器Sheet待确认。具体资产位置、身份与设计状态由[变压器唯一入口](gb20052_2024/README.md)指向，不把35表校对工作簿误作输入模板。

## 通用判定结果用语（Owner软件约定）

**本仓当前及今后接入标准的通用业务结果用语，在本节统一维护。Owner于2026-10-18确定“未达3级”“不在范围”“无法判定”；后续AI不得自行改成同义词。** 确需改变名称或含义时，由Owner明确决定，在本入口记录原因与影响；各标准映射引用本节，不再各自维护另一套通用名称。

|用户可见结果|含义与使用边界|
|---|---|
|`1级` / `2级` / `3级`|依据适用标准及已确认映射，能够确定相应等级|
|`未达3级`|已有充分依据明确判定未达到该标准3级能效要求；不是资料不足或计算失败|
|`不在范围`|有明确依据证明不属于所选标准适用范围；附具体范围原因|
|`无法判定`|当前依据不足或必要类别、分支等尚未确认，不能形成明确判定；附缺失项或未确认原因|

本表是当前三级能效体系的通用显示口径，**不是要求将底层业务和流程压成六个状态枚举**。具体标准的判定顺序、范围判断、所需字段和组合方式仍由该标准映射及已明确的软件决定规定。

- GUI、Excel、Word、API的显示文本及未来客户端使用同一结果用语；该三类结果不再以“未达标”“不适用”“无法评价”等替代名称显示。程序通过共享结果投影提供中文，保留等级、评价状态、原因、软件支持状态、执行/保存状态和记录资格；机器状态码、字段ID与数值规则不因中文名称调整而自行改变。
- 原标准中的文字、等级名称、阈值、比较方向和等号条件如实保留；映射将本约定标为【实现约定】，不得改写原文或冒称标准明文。“未达3级”不新增一个标准等级，也不单独替代法定合规判断。
- 评价结果为`INVALID_INPUT`、当前未支持、标准包读取/执行失败时，给出对应的输入、能力或系统提示，不能伪装成合法业务终态；保存失败须保留已经获得的业务结果并明确提示保存失败。上述情况不得直接写成“未达3级”，软件未支持也不得写成标准“不在范围”。
- “无法判定”的显示本身不决定能否形成Record。沿用既有结构化条件：离心泵资料不足可以是可记录终态，明确选择“不确定类别”当前仍不可形成单台Record，但批量结果保留该行；统一显示不自动改变该差别。不得根据中文文本或仅凭grade是否为空决定记录资格。
- 不在显示层重新计算适用范围或添加通用输入门禁。若某标准依据已有数据已能证明范围外，不因其他不影响该项范围依据的字段缺失或非法而改变其已批准的判定顺序；依据不足时也不得猜成“不在范围”。
- 多指标标准分别保留各指标的判定及未决状态，总体结果按本标准映射合并，不因统一名称引入通用“取最差”规则。后续标准若没有3级体系，不能凭本约定创造3级阈值；其实际结果结构在映射中如实说明。
- 历史原始快照和原文证据不因术语统一而覆盖重写；历史结果的显示可按结构化状态采用统一用语，并保留原始信息的可追溯性。四级、五级或非三级体系按标准如实承载，不因本表遗漏等级。

**与旧展示约定的关系：** 本节覆盖既有离心泵资料及`PUMP_NUMERIC_AND_DECISION_CONTRACT_V2.md`中对应的旧中文展示口径；原文、数值规则、状态、原因和历史验收事实继续保留。实施只修改实际结果显示投影及直接说明，不能全文替换原标准、冻结映射、历史快照或输入选项中的同名词。

## 目录与命名

- 每个标准版本一个目录：`<标准前缀及编号>_<年份>`；例如`gb19762_2025`、`gb20052_2024`。GB/T用`gbt`、JB/T用`jbt`；部分号保留为独立段（命名示意`gbt12345_1_2025`，不是实际建档标准）。
- 标准年份与映射修订号分开。新年份另建目录，在README注明替代关系；不得覆盖旧标准版本。文档V1.0/V2.1不作为新标准目录名。
- 一个标准覆盖多个Profile时共用目录，共同规则只写一处；分支确有需要才拆到`profiles/`。设备分类放索引，不复制同一标准到多个设备目录。
- 每个目录README明确当前有效映射、配套表值文件、原文来源/证据、相关问题及验收入口；正文每份只维护一处。旧路径可保留跳转，不保留第二套可编辑“最终版”。
- 草稿日常修订使用Git历史；已冻结修订按其批准边界另起版本并保留旧文件/SHA，README明确当前版本，不以“最新”“最终版2”命名。
- `gb20052_v21/`是已冻结档案的兼容例外，实体原位保留，统一入口为`gb20052_2024/README.md`。

|文件/目录|职责与创建时机|

## 发现问题时最小流程（每次仅处理实际遇到的项）

1. **原文先行**：找到标准版本、章/条/表/印刷页与PDF物理页。合并单元格/重复行/貌似空白时查看PDF图像。不得把OCR、旧JSON、旧Excel平铺当作唯一原文证据。
2. **复用或新增稳定编号**：检索根目录`STANDARD_ISSUES_REGISTER.md`，相同问题只补已有编号；新问题按`EQP-STD-<标准号>-NNN`递增。根台账记录标准事实、技术判断、Owner软件决定、状态、影响链。
3. **复杂问题才写解释档**：按`_STANDARD_INTERPRETATIONS_TEMPLATE.md`记录歧义、对照证据、技术解释、例子、反例和明确的未决条件。简单、明确的文义直接写根台账即可，不为记录而制造材料。
4. **问题关闭边界**：`RESOLVED`可以是【有源事实】或【Owner已批准的软件实现口径】，必须清楚注明何者；`PROVISIONAL`是有工程方案但来源/适用性未证实；`OPEN`是尚未解决。不得让“软件决定”变成“标准发布机构已解释”。
5. **检查影响**：解释可能改变适用范围、阈值、阻抗分组、插值、温度、状态、Golden时，检查Mapping、数据审计、CHANGELOG、金样/测试与已有实现；无用户授权的纯文档阶段**不改生产代码/JSON/SQLite/Golden**。
6. **长效维护**：每次新增一个标准或发现疑点，执行者先读本入口＋AGENTS§7；继续现有主分支/PR流程，不额外建立“再审批一遍”的门禁。仓库根台账永远保留已失效解释编号和修改原因。

## 规则与表值配套、核验分别留痕

**标准原文 → 主映射及已核验表格数据 → 软件实现。** 映射回答“按什么规则选表、选行和判级”，配套工作簿/数据回答“具体限值是多少”。有标准表格时同步整理条件和数值；没有表格的标准说明不适用，不强造Excel。外部Excel、历史JSON、旧代码及临时输出只作比较，不能自动成为标准事实。

**“一套核心依据”不等于“一个物理文件”。** 一个标准可由主映射、必要分支及配套已核验表值等互补文件共同组成依据；该标准唯一README列明成套成员、各自职责、相容修订及核实/批准证据，正文每份只维护一处。复杂标准可参考变压器的“规则映射＋表值工作簿”双文件方式，不强制简单标准拆分。不可只取其中一份忽略配套条件，也不为形式上的单文件而合并、复制或重存冻结资产。

1. 先理解表结构，再提取数据。同容量可有多个物理分支，损耗相同不代表分支能合并；记录表号、完整条件、单位/参考温度、源行/源格和合并覆盖范围。
2. **结构检查与数值核验分别记录**。表数、容量点、候选行数不能证明逐格值正确；数值核验包括精度和合并源格。疑似空白、重复容量、合并单元格必须核对PDF原页图像。
3. XLSX用真实Sheet/单元格坐标读取，不以第几个非空单元格代替列号。错列等发现应能以源文件SHA、坐标、提取步骤、实际/预期复现；必要时查原始XML，证据不成立时撤回发现并留痕。
4. 明确标识【标准】、【技术判断】、【实现约定】、【需确认】。项目批准和独立逐格核验分开写，文件已入库/名称正式/PR已合并均不自动证明数值已核验或问题已关闭。
5. 边界候选按适用性覆盖等号、多个指标分别比较、单位转换、温度口径、重复容量、特殊分支、合法插值、缺少端点、禁止外推与缺字段。预期独立来自原文及已确认解释，不由待验证JSON/代码反推。
6. 数据/规则修订联动检查映射、配套数据、审计记录、候选案例和根问题台账。已核验工作簿可作为生产数据生成/迁移依据；正式业务计算仍由统一软件内核执行，Excel不另建算法。

核验记录最少包含文件SHA、标准条款/表/印刷页/PDF物理页、Sheet/单元格、分支条件、检查方法、覆盖与未覆盖范围、结果和执行人/日期。必要脚本与人工复核足够，不要求每标准新增CI或审批体系。
