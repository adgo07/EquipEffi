状态：`PENDING_APPROVAL`。以下 18 条独立复核记录来源于固定技术基线 3101e05 上未改写的 0.3 `pump_water` `APPLICATION_E2E` 候选。它们不是已批准 Golden。

## 覆盖与限制

- 代表泵型：单级单吸、单级双吸、多级、轻型多级立式/卧式、管道泵。
- 能效等级：1、2、3 级均有案例，并有未达标样例。
- 其他结果：超标准范围、缺失输入、字段冲突非法输入、缺失/未知/其他类别。
- 流量边界：有 Q=4.9 的下界外侧案例；候选池不含 Q=5、Q=300 等精确等值端点。0.1 的端点材料仍为历史冻结，未晋升。

- 当前 expected calculation trace 是 0.3 候选中的原值；实现来源只锁定技术重放，不构成标准依据或业务批准。

## 人工批准操作

1. 标准负责人逐条打开复核 JSON 和引用 PDF（本机通过 `--external-evidence-root` 提供），核对输入、适用类别/表3行、公式、状态和计算 trace，并处理每条 `review_flags`。
2. 有未解决 `review_flags` 的案例只能退回，不能批准。当前三条 flagged 案例是轻型立式、轻型卧式和管道泵；需要形成新的版本化候选并重新校验，不能改写 0.3。其余案例也须各自独立作批准/退回决定。
3. 批准时填写真实 `review_owner`、带时区 RFC3339 `reviewed_at` / `approved_at`、非空 `approval_basis` 和明确 `known_limits`；正式记录的三个状态全部设为 `APPROVED`、`review_flags=[]`，版本为 `golden-case-0.4`，再放入 `golden/pump_water/`。不改 0.1 和 0.3。
4. 运行 `python tools/validate_phase1_contracts.py --negative-probe --candidate-jsonl specs/equipment_efficiency/golden/pump_e2e_v0_3_candidates.jsonl --approval-review-dir specs/equipment_efficiency/golden/pump_water_approval_review --external-evidence-root <含注册相对路径的标准目录>`。标准 PDF 不进 Git。
5. 任何输入、trace、标准依据或范围的更改先退回并形成新版本候选，不能在审批过程中直接改成 APPROVED。

本复核包只准备材料，没有代替标准负责人审批。Phase 1 仍 BLOCKED；不得宣布 PASS 或进入 Phase 2。
