## 覆盖与限制

- 代表泵型：单级单吸、单级双吸、多级、轻型多级立式/卧式、管道泵。
- 级数：1、2、3 级均有案例。
- 结果：1/2/3 级、未达标、范围外、缺失输入、字段冲突非法输入、缺失/未知/其他类别。
- 范围边界：有 Q=4.9 的标准范围外侧案例；这 18 条不含 Q=5、Q=300 等精确等值端点，0.1 历史端点案例保持冻结且未晋升。
- 标准来源：每条记录的 source sidecar 固定 GB 19762—2025 PDF 的 SHA-256、表3/公式(1)~(3)、印刷页9–10，并固定 Canonical `pump.json` SHA 与行 ID；本包不包含标准 PDF。
- 当前 `expected_calculation_trace` 是 0.3 候选值，供标准负责人复核；实现来源 hash 仅锁定技术重放，不等同标准依据或业务批准。

## 人工批准操作

1. 标准负责人逐条打开对应 JSON 和引用 PDF（本机通过 `--external-evidence-root` 提供），核对原始输入、适用泵型/表3 行、公式解释、期望状态和计算 trace。
2. 对每条明确选择批准或退回；不得批量默认批准。批准时填写真实 `review_owner`，填写带时区的 RFC 3339 `reviewed_at` 与 `approved_at`，在 `approval_basis` 写明标准条款/表行及复核结论，在 `known_limits` 保留适用边界。
3. 将该条的 schema version 改为 `golden-case-0.4`，三个状态全部设为 `APPROVED`，把记录放入 `golden/pump_water/`；不改 0.3 候选和 0.1 历史文件。
4. 运行 `python tools/validate_phase1_contracts.py --negative-probe --candidate-jsonl specs/equipment_efficiency/golden/pump_e2e_v0_3_candidates.jsonl --approval-review-dir specs/equipment_efficiency/golden/pump_water_approval_review --external-evidence-root <含注册相对路径的标准目录>`。正式 PDF 不进入 Git。
5. 任何期望结果、输入、计算 trace、标准依据或业务范围修改都应先退回为新版本候选并重新审阅，不得直接把不一致改成 APPROVED。

本复核包只建立批准机制并准备待审资料；没有标准负责人审批，不产生任何正式 0.4 Golden。
